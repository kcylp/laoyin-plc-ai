## 一、M1 编程语言体系

### 1.1 当前缺陷

- `index.html` 的顶栏只有系列选择（S7-200 SMART / S7-1200 / S7-1500），**没有编程语言选择器**。
- `prompts.js` 只有 S7-200 SMART 的 STL prompt 和 S7-1200/1500 的 SCL prompt，**没有 LAD/FBD/GRAPH 的专用 prompt**。
- 用户说"帮我写个梯形图"，AI 可能输出 ASCII 艺术而不是博途可导入的 XML。
- `sendToTia()` 里没有传语言参数，preflight 结果虽然有 `pre.language` 但这是从 XML 推断的，不是用户选的。

### 1.2 需要做什么

**HTML（`index.html`）：**
在 `.topbar` 的 `.series-select` 下方新增一行 `.lang-select`（编程语言选择器）：

```

│ [🔧 S7-200 SMART] [⚙️ S7-1200] [🏭 S7-1500]            │
├─ 编程语言 ─────────────────────────────────────────────────┤
│ [LAD 梯形图] [FBD 功能块图] [SCL 结构化文本] [STL 语句表] [GRAPH] │
└────────────────────────────────────────────────────────────┘
```

- 默认选中：S7-1200 默认 SCL，S7-1500 默认 SCL，S7-200 SMART 默认 STL（因为 S200 SMART 不支持 SCL）
- 存入 `localStorage('plcLang')`，切换系列时联动更新默认语言
- 语言选项根据系列**动态显示**：S200 SMART 只显示 LAD 和 STL（不支持 FBD/SCL/GRAPH）；S1200/1500 显示全部五种
- 每个按钮用 `data-lang="lad"` 等属性

**CSS（`style.css`）：**

**JS（`script.js`）：**

- **S7-200 SMART 不支持 SCL/FBD/GRAPH**——如果用户选了 S200 SMART 但语言下拉选了 SCL，必须自动回退到 STL 并提示原因

## 四、M4 语言→XML 映射（最关键、最危险的模块）

### 4.1 核心事实：不同语言 → 不同 XML 格式

| 语言 | XML 根元素 | 对应 XSD | NetworkSource 内容 | ProgrammingLanguage 标签 |
|---|---|---|---|---|
| **LAD 梯形图** | `<FlgNet>` | `SW.PlcBlocks.LADFBD_v5.xsd` | Parts(Access/Part/Call) + Wires(Powerrail/NameCon/IdentCon) | `<ProgrammingLanguage>LAD</ProgrammingLanguage>` |
| **FBD 功能块图** | `<FlgNet>` | `SW.PlcBlocks.LADFBD_v5.xsd` | 同 LAD（FBD 和 LAD 共用 FlgNet 格式） | `<ProgrammingLanguage>FBD</ProgrammingLanguage>` |
| **SCL 结构化文本** | `<StructuredText>` | `SW.PlcBlocks.SCL_v4.xsd` | Token 序列（文本指令） | `<ProgrammingLanguage>SCL</ProgrammingLanguage>` |
| **STL 语句表** | `<StatementList>` | `SW.PlcBlocks.STL_v5.xsd` | Token 序列 | `<ProgrammingLanguage>STL</ProgrammingLanguage>` |
| **GRAPH** | `<Graph>` | `SW.PlcBlocks.Graph_v6.xsd` | 步/转换结构 | `<ProgrammingLanguage>Graph</ProgrammingLanguage>` |

### 4.2 每种语言的 XML 外壳（共用）

```xml
<?xml version="1.0" encoding="utf-8"?>
<Document>
  <Engineering version="V21" />
  <DocumentInfo>...</DocumentInfo>
  <SW.Blocks.{FC|FB|DB} ID="0">
    <AttributeList>
      <AutoNumber>true</AutoNumber>
      <Name>{块名}</Name>
      <Namespace />          <!-- 必须有，空的 -->
      <Number>{编号}</Number>
      <ProgrammingLanguage>{LAD|FBD|SCL|STL|Graph}</ProgrammingLanguage>
      <Interface>...</Interface>
      <!-- ...其他属性 -->
    </AttributeList>
    <ObjectList>
      <SW.Blocks.CompileUnit ID="10" CompositionName="CompileUnits">
        <AttributeList>
          <NetworkSource>
            {根据语言不同，放不同的内容}
          </NetworkSource>
          <ProgrammingLanguage>{同上}</ProgrammingLanguage>
        </AttributeList>
      </SW.Blocks.CompileUnit>
    </ObjectList>
  </SW.Blocks.{FC|FB|DB}>
</Document>
```

### 4.3 AI 生成策略

**关键决策：AI 生成什么格式？**

| 语言 | AI 应该生成 | 格式精确度要求 |
|---|---|---|
| **SCL** | **纯 SCL 文本代码**（不是 XML）| 只要语法正确即可，博途直接粘贴 |
| **STL** | **纯 STL 指令表文本** | 同上 |
| **LAD** | **ASCII 梯形图 + 底部附带完整 FlgNet XML** | XML 必须严格符合四条硬规则 |
| **FBD** | **ASCII 功能块图 + 底部附带完整 FlgNet XML** | 同 LAD |
| **GRAPH** | **步骤描述 + 底部附带 Graph XML** | 极难，AI 很难正确生成 |

**原因：SCL/STL 是文本语言，用户可以直接复制到博途粘贴，不需要走 XML Import。只有 LAD/FBD/GRAPH 是图形化语言，必须走 XML Import。**

### 4.4 对 prompts.js 的改造（M5）

**每个系列 × 每种语言 = 独立的 system prompt。**

命名规则：`{series}_{lang}`，如 `s1200_lad`, `s1200_scl`, `s7200_stl`。

#### SCL prompts（已有，微调）

现有 `s1200` 和 `s1500` prompt 已经是 SCL 为主，基本可用。需要的改动：
- 加入明确的输出格式要求：**只输出 SCL 代码，不要输出 XML**
- 加入完整的 FB/FC 声明模板
- 加入"如果需要导入博途，请直接复制以下代码到 SCL 编辑器"的提示

#### LAD prompts（新建，最关键）

LAD 提示词必须包含：
1. **FlgNet XML 的精确格式说明**（引用黄金样板 `samples\LAD_块级导入_起保停.xml` 里的注释）
2. **四条硬规则**（逐条列出，违反就失败）
3. **元件→FlgNet 的映射表**：
   - 常开触点 = `<Part Name="Contact" UId="xx" />` + `<IdentCon UId="变量UId" />`
   - 常闭触点 = `<Part Name="Contact" UId="xx"><Negated Name="operand" /></Part>`
   - 输出线圈 = `<Part Name="Coil" UId="xx" />`
   - Set 线圈 = `<Part Name="CoilSet" UId="xx" />`
   - Reset 线圈 = 未知格式（**禁止手猜，见 §4.6 坑1**）
   - TON 定时器 = 未知格式（**禁止手猜，见 §4.6 坑2**）
3. **UId 唯一性规则**：每个元件和变量引用都必须有唯一 UId
4. **Wire 连接规则**：Powerrail→Contact.in, Variable.UId→Contact.operand, Contact.out→Coil.in
5. **最终输出格式**：先输出中文逻辑说明，再输出完整块级 XML（包含 `<Document>` 外壳）

#### STL prompts（已有 S7-200 SMART 的，补充 S1200/1500 的）

S7-200 SMART 的 STL prompt 已经很详细。S1200/1500 的 STL 需要：
- 与 SCL 类似的变量声明区
- STL 指令集参考（与 S7-200 SMART 不同，1200/1500 的 STL 是 IEC 标准）

#### FBD prompts（新建）

FBD 与 LAD 共用 FlgNet 格式，但元件不同：
- 功能块用 `<Call>` 而不是 `<Part>`
- 图标不同但 XML 结构类似
- 参考 `SW.PlcBlocks.LADFBD_v5.xsd` 里的 `Call_T` 定义

#### GRAPH prompts（暂不实现）

GRAPH 太复杂，AI 难以正确生成完整的 Graph XML。**建议先标记为"即将支持"，暂时禁用**。

### 4.5 后端处理链路

```
前端发送 { message, series, lang, modelId }
  → server.js /api/chat
  → prompts.js 按 {series}_{lang} 取 system prompt
  → AI 生成响应（可能是纯文本代码，也可能是 XML，取决于语言）
  → 前端渲染代码块

用户点「发送至博途」
  → 前端识别代码块是 XML（检查 `<FlgNet` 或 `<StructuredText` 或 `<Document`）
  → 如果是纯文本代码（SCL/STL），提示"请复制到博途粘贴"，禁用发送按钮
  → 如果是 XML，走现有的 preflight → confirm → import 流程
```

### 4.6 必须告诉 Codex 的坑（历史教训）

**坑1：Reset 线圈格式未知**

`star_delta_fb.xml` 里的 `<Part Name="CoilReset" />` 是手猜的，**从未验证过**。

正确做法：
```
1. 在博途里手动建一个临时 FB
2. 放一个 Reset 线圈（SCL 里是 "Reset" 指令）
3. Connect-YinPortal → Export-YinBlockXml 导出
4. 读真实 XML 看 Reset 线圈的 FlgNet 格式
5. 把真实格式写入提示词模板
```

**绝对禁止在提示词里写未经验证的元件格式。宁可说"此元件格式待验证"也不输出错误格式。**

**坑2：TON/TOF/TP 定时器的 FlgNet 格式未知**

`star_delta_fb.xml` 里的 TON 表示是手猜的，**有至少三处错误**：
- 缺少 PT（预设时间）输入引脚
- 缺少 Q（完成位）输出引脚
- 缺少 ENO 输出
- `<TemplateValue Name="time_type">` 可能不是正确的泛型表示

验证方法同上：建临时 FB → 放 TON → 导出 → 读真实格式。

**坑3：根 `<Document>` 和块元素都不带 xmlns**

违反报错：`Missing 'Namespace' identifier attribute from the '0' object at line number 7`

正确格式：
```xml
<Document>          ← 无 xmlns
  <SW.Blocks.FB>    ← 无 xmlns
    <AttributeList>
      <Namespace />  ← 空的，必须有
```

**坑4：Parts 下 Access/Part/Call 必须平级**

违反报错：`An instruction with the name 'Access' cannot be found`

错误写法：
```xml
<Parts>
  <Part Name="Access">        ← 错！Access 不是 Part 的一种
    <Symbol>...</Symbol>
  </Part>
</Parts>
```

正确写法：
```xml
<Parts>
  <Access UId="31" Scope="LocalVariable">  ← 顶层平级
    <Symbol><Component Name="Start" /></Symbol>
  </Access>
  <Part Name="Contact" UId="21" />          ← 平级
</Parts>
```

**坑5：常闭触点不是 ContactNot**

违反报错：`An instruction with the name 'ContactNot' cannot be found`

正确写法：
```xml
<Part Name="Contact" UId="22">
  <Negated Name="operand" />    ← Negated 的 Name 属性必须写 "operand"
</Part>
```

`Negated` 必须带 `Name` 属性指明取反哪个引脚。空 `<Negated />` 也会失败。

**坑6：FlgNet xmlns 校验前必须剥掉**

`SW.PlcBlocks.LADFBD_v5.xsd` **没有 targetNamespace**。如果 FlgNet 带着 xmlns 送去校验，XSD 找不到元素声明。

引擎 `engineer-yin-bridge.js` 的 `extractFragments()` 已经处理了这个（调 `stripNamespaces()`），但如果 Codex 写新的校验逻辑，必须也剥。

**坑7：S7-200 SMART 不支持 XML Import**

S7-200 SMART 的编程软件（STEP 7-MicroWIN SMART）**没有 Openness API**。不能走 XML Import 路线。

只有 S7-1200 和 S7-1500 支持博途 Openness XML Import。S7-200 SMART 只能走"AI 生成 STL 代码 → 用户手动复制粘贴"路线。

**坑8：PS5.1 GBK 陷阱**

写任何 `.ps1` 文件时，**内容必须纯 ASCII**。中文只能放进 XML 或数据文件。

违反后果：PS5.1 按 GBK 读 UTF-8 无 BOM 的 .ps1 → 中文和引号乱码 → 脚本解析崩溃。

**坑9：V21 程序集不能广度反射**

对 `Siemens.Engineering.dll` 做 `GetMethods()` 会 StackOverflow 杀进程。

只能用 `Get-YinType` 按全名精确取类型。如果需要泛型方法，用反射绑定。

**坑10：旧桌面副本随时被删**

`Desktop\5\plc-ai-assistant` 和 `Desktop\EngineerYin` 是旧的，用户随时会删。**不要读、不要改、不要引用。** 唯一有效路径是 `F:\工控软件\老殷工控PLC助手\`。

#### 邮件回复监听（核心难点）

**问题：SMTP 是发邮件的，不能收邮件。收邮件需要 IMAP/POP3。**

方案选择：

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A. QQ邮箱 IMAP 轮询** | 实现简单，QQ邮箱支持 IMAP | 需要开启 QQ邮箱 IMAP 服务 + 定时轮询 |
| **B. 链接审批（当前已有）** | 已实现，稳定 | 不是"回复邮件"，要打开链接 |
| **C. 微信通知 + 回复** | 更方便 | 依赖微信，复杂 |

**推荐方案 A + B 结合：**

1. **保留链接审批**（`/api/approve?userId=X&action=approve&adminKey=XXX`）——你点击链接就能审批
2. **新增 IMAP 轮询**——定时检查你邮箱里有没有新回复，自动识别"同意/不同意"

#### IMAP 邮件轮询实现

```javascript
// 新文件：mail-watcher.js
const Imap = require('imap');
const { simpleParser } = require('mailparser');

const imapConfig = {
    user: process.env.SMTP_USER,       // 你的邮箱
    password: process.env.SMTP_PASS,   // 授权码
    host: 'imap.qq.com',               // QQ邮箱 IMAP
    port: 993,
    tls: true
};

function startMailWatcher(db) {
    const imap = new Imap(imapConfig);
    
    imap.once('ready', () => {
        imap.openBox('INBOX', true, (err, box) => {
            // 每 30 秒检查一次新邮件
            setInterval(() => {
                imap.search(['UNSEEN', ['FROM', process.env.SMTP_USER]], (err, results) => {
                    if (!results.length) return;
                    const f = imap.fetch(results, { bodies: '' });
                    f.on('message', (msg) => {
                        msg.on('body', (stream) => {
                            simpleParser(stream, (err, parsed) => {
                                handleReply(parsed, db);
                            });
                        });
                    });
                });
            }, 30000);
        });
    });
    
    imap.connect();
}

function handleReply(parsed, db) {
    const text = (parsed.text || '').toLowerCase();
    const subject = parsed.subject || '';
    
    // 从主题里提取用户ID：「Re: 【新用户】张三 注册了老殷工控PLC」
    const match = subject.match(/userId[=:](\d+)/i);
    if (!match) return;
    const userId = parseInt(match[1]);
    
    if (text.includes('同意') || text.includes('approve') || text.includes('通过')) {
        db.prepare('UPDATE users SET status = ? WHERE id = ?').run('approved', userId);
        // 给用户发同意通知
    } else if (text.includes('不同意') || text.includes('reject') || text.includes('拒绝')) {
        db.prepare('UPDATE users SET status = ? WHERE id = ?').run('rejected', userId);
        // 给用户发拒绝通知
    }
}
```
