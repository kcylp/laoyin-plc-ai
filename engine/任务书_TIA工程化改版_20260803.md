## 五、`script.js` 增量改造

### 5.1 不许动的部分（碰坏就是返工）

| 代码位置 | 为什么不能动 |
|---|---|
| `getAIResponse()` 里的 SSE 读取循环 | `buffer.split('\n\n')` + `lines.pop()` 的粘包处理是调通过的 |
| `formatMessage()` 的四步顺序 | **先抽代码块占位 → 行内码 → 换行/粗体/标题/列表 → 回填代码块**。顺序一变，XML 里的 `**` `-` 会被 markdown 规则污染 |
| `escapeHtml()` / `escapeAttr()` | 复制出去必须是原始 XML，不是实体编码。`data-code` 存的是 `escapeAttr` 后的值，`copyCode` 取出来直接写剪贴板——这条链路已验证 |
| `checkAuthentication()` | JWT 校验与跳转逻辑 |
| `preflight → confirm → import` 三步 | 安全链路，只许把 `window.confirm` 换成自定义模态，**步骤不许合并** |

### 5.4 改造：代码块按钮矩阵（关键）

现有判定过于宽松（`isXml = /xml/i.test(lang) || /<FlgNet/ || /<Document/`），
且**所有 XML 都给了「发送至博途」按钮**——SCL/STL 纯文本也可能误命中。改为：

```js
function identifyCode(lang, code) {
  // 1) 先按 XML 根元素判语言（最可靠）
  if (/<FlgNet[\s>]/i.test(code)) {
    // FlgNet 是 LAD 与 FBD 共用的，用块内 ProgrammingLanguage 区分
    const m = code.match(/<ProgrammingLanguage>\s*(LAD|FBD)\s*</i);
    return { kind: 'xml', lang: m ? m[1].toLowerCase() : 'lad', canSend: true };
  }
  if (/<Graph[\s>]/i.test(code))          return { kind: 'xml', lang: 'graph', canSend: true };
  if (/<StructuredText[\s>]/i.test(code)) return { kind: 'xml', lang: 'scl',   canSend: false };
  if (/<StatementList[\s>]/i.test(code))  return { kind: 'xml', lang: 'stl',   canSend: false };
  if (/<Document[\s>]/i.test(code))       return { kind: 'xml', lang: 'unknown', canSend: false };
  // 2) 不是 XML = 纯文本代码
  return { kind: 'text', lang: (lang || '').toLowerCase() || null, canSend: false };
}
```

按钮矩阵（**验收会逐项核**）：

| 代码块类型 | 复制 | 下载 XML | 校验 XSD | 发送至博途 |
|---|:--:|:--:|:--:|:--:|
| XML · LAD | ✅ | ✅ | ✅ | ✅ |
| XML · FBD | ✅ | ✅ | ✅ | ✅ |
| XML · GRAPH | ✅ | ✅ | ✅ | ✅ |
| XML · SCL | ✅ | ✅ | ✅ | ❌ |
| XML · STL | ✅ | ✅ | ✅ | ❌ |
| XML · 未识别 | ✅ | ✅ | ✅ | ❌ |
| 纯文本（SCL/STL 源码） | ✅ | ❌ | ❌ | ❌ |

> **GRAPH 拿到 `canSend:true`** —— 这是本次和上一版最大的区别（见 §7）。
> SCL/STL 的 XML 形态也能技术上导入，但推荐直接粘贴，故不给写入按钮；
> 若后续要放开，改这张表一处即可。

校验 XSD 调用时把识别出的语言带上：
```js
body: JSON.stringify({ xml: code, lang: identified.lang })
```

## 七、GRAPH 必须可用（本次重点）

上一版任务书写的是「GRAPH 暂时禁用」。**本版必须做通。** 下面是唯一被认可的路径。

### 7.1 为什么 GRAPH 比 LAD 难

GRAPH（顺序功能图 / S7-GRAPH）不是 FlgNet，它有自己一套结构：

- 根元素是 `<Graph>`，XSD 是 `SW.PlcBlocks.Graph_v6.xsd`（引擎里已有，13,542 字节）
- 内容是**步（Step）+ 转换（Transition）+ 动作（Action）+ 互锁/监视（Interlock/Supervision）**
- 每个 Transition 内部还嵌一段 **FlgNet**（转换条件用 LAD 画）——即 Graph 是 FlgNet 的**超集**
- GRAPH 块**只能是 FB**（需要状态存储），必须配背景 DB
- 步与转换的 UId／Number 有强一致性约束，乱了直接导入失败

### 7.2 强制验证路径（禁止跳步，禁止手猜格式）

```
第 1 步：在博途 V21 里手动建一个最小 GRAPH FB
   - 新建 FB，语言选 GRAPH
   - 画 2 步 1 转换：Step1 →(转换条件 I0.0)→ Step2
   - Step1 加一个动作（置位 Q0.0），Step2 加一个动作
   - 编译通过、保存

第 2 步：导出真实 XML 当模板
   Connect-YinPortal
   Export-YinBlockXml -BlockName "<你建的GRAPH块名>" -OutDir "$env:TEMP\graph_ref"

第 3 步：逐段读导出的 XML，把真实结构记录成模板
   要记清：<Graph> 的属性、Step/Transition 的 UId 与 Number 规则、
           Action 的表示、Transition 里 FlgNet 的嵌套位置与 xmlns 情况

第 4 步：XSD 自校验闭环
   把导出的真实 XML 原样送 Test-YinFlgNet -SchemaFile 'SW.PlcBlocks.Graph_v6.xsd'
   —— 必须 Valid=true。若不通过，说明校验前的 xmlns 剥离/片段抽取有问题，
      先修 engineer-yin-bridge.js 的 extractFragments/stripNamespaces，别改 XML

第 5 步：原样导回（改个名避重名）

第 6 步：把已验证的真实结构写进 prompts.js 的 GRAPH 提示词
   —— 提示词里的每一个元素名、属性名，都必须能在第 2 步导出的文件里找到原文

第 7 步：让 AI 按提示词生成一个新 GRAPH（如"三步顺控：进料→加热→出料"）
   → 前端「校验 XSD」通过 → 「发送至博途」→ 编译 0 错 0 警
```

### 9.3 LAD 提示词里必须写死的四条硬规则

这四条是踩坑换来的，**每条都要在提示词里原文出现**，让模型不会犯：

```

       不是 <Part Name="Access">
       违反报错：An instruction with the name 'Access' cannot be found

规则3  常闭触点 = <Part Name="Contact"><Negated Name="operand" /></Part>

规则4  <FlgNet> 元素带 xmlns=".../FlgNet/v4"，但送 XSD 校验前必须剥掉

```
