## 〇、结论先行：走「受控 Import 迭代法」，放弃 GUI 点击

### 为什么放弃 GUI 自动化

上一轮实测已证明：

- TIA V21 的 LAD 画布是 WPF 自绘，**工具按钮不可由 UIA 命名识别**
- Windows 缩放导致逻辑像素/物理像素坐标漂移
- 前台焦点会被其他应用抢走，继续硬点有**误改其他 Network 甚至其他窗口**的真实风险
- `Ref_TonSetReset [FB2]` 编译失败点是 `Network 1 的 TON IN 直连母线 → A preceding Boolean logic operation is missing`
- **块不一致 → 导出被拒**：`Inconsistent blocks and PLC data types (UDT) cannot be exported`

**并且这里有一个上一轮没意识到的事实**：
Network 2（`%M0.1` 置位线圈）和 Network 3（`%M0.1` 复位线圈）**同样缺前置布尔逻辑**，
病因与 Network 1 完全一致。博途只报第一条错，所以"失败点很明确"其实是**三条错里的第一条**。
GUI 路线的真实工作量是三倍，不是补一个触点就能收工。

### 为什么 Import 迭代法是确定性的

- 不需要任何屏幕坐标、不抢焦点、不受 DPI 影响
- **博途 Import 失败时会主动列出该位置的合法元素清单**（当初打通 LAD 常闭触点就是靠这个：
  它自己列出了 `Equation, Instance, TemplateValue, AutomaticTyped, Invisible, Negated, Comment`）
- 不需要块先编译通过——Import 是拿格式的手段，编译是最后的验收
- 一旦 Import 成功，**再 Export 一次**就拿到博途自己的规范化序列化（可能补上我们没写的元素），
  这份导出才是最终写进提示词的 ground truth

## 一、已确认的硬事实（可直接用，不要再调研）

### 1.1 逐字真实模板：FB 调用（来自 TiaCommander 发行包 `Templates\diagnostics\TC_DiagOB.xml`）

```xml
<Parts>
  <Call UId="21">
    <CallInfo Name="TC_Diag" BlockType="FB">
      <Instance Scope="GlobalVariable" UId="22">
        <Component Name="TC_Diag_DB" />
      </Instance>
    </CallInfo>
  </Call>
</Parts>
<Wires>
  <Wire UId="23">
    <Powerrail />
    <NameCon UId="21" Name="en" />
  </Wire>
</Wires>
```

**这是本次攻坚最重要的一块拼图。** 要点：
- FB 调用用 `<Call>`，**不是** `<Part>`
- 块名在 `<CallInfo Name="..." BlockType="FB">`
- 背景 DB 用 `<Instance Scope="..." UId="...">` + `<Component Name="..."/>`，是 `CallInfo` 的子元素
- 使能引脚名是小写 `en`

### 1.2 逐字真实模板：普通线圈（同上，`Templates\Ob.xml`）

```xml
<Access Scope="GlobalVariable" UId="21"><Symbol><Component Name="Tag_1" /></Symbol></Access>
<Part Name="Contact" UId="23" />
<Part Name="Coil" UId="24" />
...
<Wire UId="25"><Powerrail /><NameCon UId="23" Name="in" /></Wire>
<Wire UId="26"><IdentCon UId="21" /><NameCon UId="23" Name="operand" /></Wire>
<Wire UId="27"><NameCon UId="23" Name="out" /><NameCon UId="24" Name="in" /></Wire>
<Wire UId="28"><IdentCon UId="22" /><NameCon UId="24" Name="operand" /></Wire>
```

与本项目黄金样板 `samples\LAD_块级导入_起保停.xml` **完全一致**，交叉验证通过。

### 1.3 XSD 层面的强约束（读自 `schemas\SW.PlcBlocks.LADFBD_v5.xsd`）

| 事实 | 位置 | 含义 |
|---|---|---|
| `<Parts>` 下只允许 `Access` / `Part` / `Call` 三者平级 | 113-120 行 | `Call` 是独立一类，不是 `Part` 的变体 |
| `Part_T` 首子元素是 `xs:choice`：`Equation` 或 **`Instance`** | 82-91 行 | `Part` 也能带 `<Instance>`（`Equation` 仅 Calculate 用） |
| `PartSequence_G` 是 `xs:sequence`，顺序**锁死** | 121-129 行 | `TemplateValue → AutomaticTyped → Invisible → Negated → Comment`，且 `Instance` 排在这组之前。顺序写反 XSD 直接拒 |
| `Instance_T` 定义在 `Access_v5.xsd:310-311` | — | 内容是 `Component`/`AbsoluteOffset`/`Token`/`Address`，即一条符号路径 |
| **`PinName_TE` = `xs:restriction base="xs:string"`，无枚举** | 130-132 行 | ⚠️ **引脚名写什么 XSD 都放行** |

### 1.4 ⚠️ 最关键的方法论结论

> **XSD 校验通过 ≠ 格式正确。**
> 因为 `PinName_TE` 无枚举，`Name="IN"` / `Name="in"` / `Name="乱写"` 一律通过 XSD。
> **引脚名、指令名是否合法，只有博途 Import 能验。**
>
> 所以验证门禁必须是两道：**先 XSD（挡结构错）→ 再 Import（挡语义错）→ 最后 Compile（挡逻辑错）**。
> 任何"XSD 过了就写进提示词"的做法都是错的。

|---|---|

### 2.1 TON 定时器 —— 逐字真实格式

**先纠正一个错误推测**：TON **是 `<Part>`，不是 `<Call>`**。
`<Call>` 用于自定义 FB/FC 调用；IEC 定时器是**内建指令**，走 `<Part>` + `<Instance>`。

完整网络（触点 → TON，PT 由类型化常量给定），逐字：

```xml
<NetworkSource><FlgNet xmlns="http://www.siemens.com/automation/Openness/SW/NetworkSource/FlgNet/v4">
  <Parts>
    <Access Scope="GlobalVariable" UId="21">
      <Symbol>
        <Component Name="Sensor Wals (Option)" />
      </Symbol>
    </Access>
    <Access Scope="TypedConstant" UId="22">
      <Constant>
        <ConstantValue>T#1s</ConstantValue>
      </Constant>
    </Access>
    <Part Name="Contact" UId="23" />
    <Part Name="TON" Version="1.0" UId="24">
      <Instance Scope="GlobalVariable" UId="25">
        <Component Name="IEC_Timer_0_DB" />
      </Instance>
      <TemplateValue Name="time_type" Type="Type">Time</TemplateValue>
    </Part>
  </Parts>
  <Wires>
    <Wire UId="27">
      <Powerrail />
      <NameCon UId="23" Name="in" />
    </Wire>
    <Wire UId="28">
      <IdentCon UId="21" />
      <NameCon UId="23" Name="operand" />
    </Wire>
    <Wire UId="29">
      <NameCon UId="23" Name="out" />
      <NameCon UId="24" Name="IN" />
    </Wire>
    <Wire UId="30">
      <IdentCon UId="22" />
      <NameCon UId="24" Name="PT" />
    </Wire>
    <Wire UId="31">
      <NameCon UId="24" Name="ET" />
      <OpenCon UId="26" />
    </Wire>
  </Wires>
</FlgNet></NetworkSource>
```

### 2.2 ⚠️ TON 的五条反直觉规则（每条都必须写死，违反必失败）

| # | 规则 | 证据强度 |
|---|---|---|
| 1 | **`Version="1.0"` 是强制属性** | 35+ 次 TON 出现，100% 都带 |
| 2 | **定时器引脚名大写：`IN` / `PT` / `Q` / `ET`**；而触点线圈引脚仍是**小写** `in` / `out` / `operand` | 全部样本一致。这种混合大小写是**真的**，不是笔误 |
| 3 | **`ET` 即使不使用也必须接线**，接到 `<OpenCon UId="n" />` | 每个样本都接；无一省略 |
| 4 | **TON 没有 ENO 引脚**。grep 全部真实导出，`eno`/`ENO` **零命中** | TON 在 LAD 里不是 EN/ENO 框。（`DisabledENO="true"` 确实存在，但只出现在数学框如 `<Part Name="Inc" DisabledENO="true">`） |
| 5 | **子元素顺序：`<Instance>` 必须在 `<TemplateValue>` 之前** | XSD `Part_T` 强制（choice(Equation\|Instance) → PartSequence_G） |

`<TemplateValue Name="time_type" Type="Type">Time</TemplateValue>`
—— 注意是 `Type="Type"`，**不是** `Type="Cardinality"`。

### 2.3 TON 实例的三种写法（都是真实导出）

**A. 全局背景 DB（最常见）**
```xml
<Instance Scope="GlobalVariable" UId="25">
  <Component Name="IEC_Timer_0_DB" />
</Instance>
```

**B. 全局 DB + 导出时附带的地址信息**（`Informative="true"` 是博途自己加的，导入时可省）
```xml
<Part Name="TON" Version="1.0" UId="26">
  <Instance Scope="GlobalVariable" UId="27">
    <Component Name="TON_TEST_SAFETY" />
    <Address Area="DB" Type="IEC_TIMER" BlockNumber="42" BitOffset="0" Informative="true" />
  </Instance>
  <TemplateValue Name="time_type" Type="Type">Time</TemplateValue>
</Part>
```

**C. FB 内部多重实例（Static 成员）← 本项目星三角 FB 要用这种**
```xml
<Part Name="TON" Version="1.0" UId="32">
  <Instance Scope="LocalVariable" UId="33">
    <Component Name="TO_Non_filter" />
  </Instance>
  <TemplateValue Name="time_type" Type="Type">Time</TemplateValue>
</Part>
```

> 星三角 FB 的 Static 区已声明 `Timer : TON_TIME`，对应就是 **写法 C**（`Scope="LocalVariable"`）。

### 2.4 读 TON 的 Q 输出：两种真实写法

**A. 直接连线**（TON.Q → 下一个元件的输入）
```xml
<Wire UId="37">
  <NameCon UId="26" Name="Q" />
  <NameCon UId="28" Name="IN" />
</Wire>
```

**B. 作为独立符号访问**（即 `T0.Q`，多级 `<Component>`）
```xml
<Access Scope="GlobalVariable" UId="25">
  <Symbol>
    <Component Name="T0" />
    <Component Name="Q" />
  </Symbol>
</Access>
```

### 2.5 置位线圈 SCoil / 复位线圈 RCoil —— 逐字真实格式

**指令名是 `SCoil` / `RCoil`，不是手猜的 `CoilSet` / `CoilReset`。**

```xml
<Part Name="Contact" UId="23" />
<Part Name="SCoil" UId="24" />
...
<Wire UId="27">
  <NameCon UId="23" Name="out" />
  <NameCon UId="24" Name="in" />
</Wire>
<Wire UId="28">
  <IdentCon UId="22" />
  <NameCon UId="24" Name="operand" />
</Wire>
```

复位线圈把 `SCoil` 换成 `RCoil`，其余完全相同：`<Part Name="RCoil" UId="24" />`

要点：
- **无 `Version` 属性**（与 TON 不同）
- **无子元素**，裸元素自闭合
- 引脚 `in` / `operand`，**小写**（与普通 `Coil` 结构完全一致）

佐证计数（真实导出）：`ArvidHS/MainPLS_Greider` 有 20 SCoil + 21 RCoil + 22 TON；
`islamlab/Robot-Arm-Sorting-FactoryIO` 有 16 SCoil + 19 RCoil + 10 TON；
`gabrieleNaso/PLConversionTool` 有 2 SCoil + 5 RCoil。

### 2.6 TOF 顺带确认

`<Part Name="TOF" Version="1.0" UId="28">` + 同样的 `time_type` TemplateValue，模式与 TON 完全一致。

### 2.7 ⚠️ 待核实项：FlgNet namespace 版本（v4 vs v5）

调研给出的版本映射（来源：`Parozzz/TiaUtilities` 的 `SimaticMLAPI.cs`）：

| namespace | 对应 TIA 版本 |
|---|---|
| `.../FlgNet/v3` | V16 |
| `.../FlgNet/v4` | V17 / V18 |
| **`.../FlgNet/v5`** | **V19 及以上（含 V21）** |

**但本项目现状是 v4**：
- 黄金样板 `samples\LAD_块级导入_起保停.xml` 用 v4，**且已在 V21 上实机导入 + 编译 0 错 0 警**
- `star_delta_fb.xml` 也写 v4
- TiaCommander 的模板用 **v5**

**结论：v4 在 V21 上确实能用（有实测证据），不要因为调研说"V21 该用 v5"就贸然全局改。**
本次按 §4 步骤 0 单独做一次 A/B 实验确认，**在拿到结论前一律沿用 v4**（已验证路径优先）。

> 无论 v4 还是 v5，**送 XSD 校验前都要剥掉 xmlns**（官方 LADFBD XSD 无 targetNamespace），
> 引擎 `stripNamespaces()` 已处理。

### 2.8 补充：Wire 端点的完整合法集合

XSD `Wire_T`（134-143 行）允许五种子元素，之前只用过前三种：

| 元素 | 用途 |
|---|---|
| `<Powerrail />` | 左母线 |
| `<NameCon UId Name />` | 接命名引脚 |
| `<IdentCon UId />` | 接操作数（指向 `<Access>`） |
| **`<OpenCon UId />`** | **悬空端点 ← TON 的 ET 必须用它** |
| `<Openbranch />` | 开放分支 |

### 步骤 1：构造验证块 `Ref_TonSR_Verify`

新建一个 FB 的块级 XML，**三个网络覆盖三个待验证元件**，每个网络都带合法前置布尔逻辑
（这正是 GUI 版失败的原因——本次由 XML 直接给出，不会再犯）：

```
Network 1  Start(常开) → TON(IN)，PT=T#1s，ET→OpenCon，Q→Done(线圈)
Network 2  Trig(常开) → SCoil(Latch)
Network 3  Rst(常开)  → RCoil(Latch)
```

接口设计（**用 FB 局部变量，不用 %M0.0 全局地址**——避免与全局变量表耦合，
且导出的 `<Access Scope="LocalVariable">` 与本项目要生成的块结构一致）：

```xml
<Section Name="Input">
  <Member Name="Start" Datatype="Bool" />
  <Member Name="Trig"  Datatype="Bool" />
  <Member Name="Rst"   Datatype="Bool" />
</Section>
<Section Name="Output">
  <Member Name="Done"  Datatype="Bool" />
  <Member Name="Latch" Datatype="Bool" />
</Section>
<Section Name="Static">
  <Member Name="Timer" Datatype="TON_TIME" />   <!-- 多重实例，对应 §2.3 写法 C -->
</Section>
```

构造要点（照 §2 抄，不要自己发挥）：
- TON：`<Part Name="TON" Version="1.0" UId="x">` + `<Instance Scope="LocalVariable">` + `<TemplateValue>`
- TON 引脚大写 `IN`/`PT`/`Q`/`ET`；触点线圈小写 `in`/`out`/`operand`
- `ET` 接 `<OpenCon UId="n" />`
- PT 用 `<Access Scope="TypedConstant"><Constant><ConstantValue>T#1s</ConstantValue></Constant></Access>`
- SCoil / RCoil 裸元素，无 Version 无子元素
- 块外壳：根 `<Document>` 与 `<SW.Blocks.FB>` **都不带 xmlns**，AttributeList 内有空 `<Namespace />`
- UId 全局唯一

存到 `%TEMP%\Ref_TonSR_Verify.xml`（**不要放 Temp 当最终产物**，验证成功后另存进 samples/）

### 步骤 2：三道门禁依次过

```
门禁一  XSD 校验（挡结构错）
        Import-YinBlock 内置校验，或直接 Test-YinFlgNet -SchemaFile 'SW.PlcBlocks.LADFBD_v5.xsd'
        ⚠️ 记住 §1.4：XSD 过了不代表格式对（PinName 无枚举）

        这是确定性收敛，不是猜

        Invoke-YinCompile
        必须 0 错 0 警。有错就读诊断改 XML，别改博途
```

### 步骤 3：反向导出拿规范化版本（关键，别跳）

Import 成功后**再导出一次**：

```powershell
Export-YinBlockXml -BlockName "Ref_TonSR_Verify" -OutDir "$env:TEMP\ref_out"
```

**为什么必须做这一步**：博途会把我们写的 XML 规范化，可能
- 补上我们没写的元素（如 `<Address ... Informative="true">`）
- 调整属性顺序
- 显式化默认值

**这份导出才是写进提示词的最终 ground truth**，比我们手写的输入更权威。
