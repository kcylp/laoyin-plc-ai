# 构建、发布与客户部署手册

> 适用于 GitHub 源码、源码交接 ZIP 和绿色免安装 ZIP。请把本手册与最终交付报告一起交给客户技术负责人。

## 0. 交付形态和诚实边界

本项目有三种交付物：

1. GitHub 源码：可审查、可修改、可自行构建。
2. 源码交接 ZIP：从最终 Git HEAD 归档，附 manifest 与交接说明。
3. 绿色免安装 ZIP：Windows 完整解压目录，内含启动器、SEA 服务、外置前端和 TIA/EngineerYin 资产。

三者均不得包含发行方真实 API Key、SMTP/IMAP 授权码、JWT 生产密钥、ADMIN_KEY、.env、数据库、授权文件、运行日志、用户数据或测试缓存。客户必须配置自己的凭据。

绿色包不是 TIA Portal 安装器。TIA Portal、Openness/PublicAPI、许可证、Windows 用户组和 AllowList 必须由客户在自己的电脑合法安装和配置。V21 MCP 不能冒充 V18/V19/V20。

源码完整交给客户后，客户能够读取并修改离线授权逻辑；“毫无保留交源码”和“源码接收者绝对无法绕过授权”无法同时成立。若商业上需要不可绕过，应改为公钥签名许可证或在线授权服务，并另立需求。

## 1. 发布前冻结顺序

1. 确认工作区没有意外 .env、数据库、授权文件、日志、截图和真实 Key。
2. 读取 package.json、README 和 docs/handoff，确认版本、限制和客户配置要求。
3. 运行：

~~~powershell
node --check tia-mcp-client.js
node --test test/tia-mcp-client.test.js
npm test
git diff --check
~~~

4. 如果改过 TIA C#，先检查本机是否有 .NET Framework 4.8 Developer/Targeting Pack。没有就记录源码已改、runtime 未重编译，不得把源码改动写成 runtime 已生效。
5. 构建绿色包：

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\work\green-build\build-green.ps1
~~~

6. 运行绿色包门禁：

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\work\green-build\verify-final.ps1
~~~

7. 记录 ZIP 字节数、SHA256、构建时间、冷启动耗时和验证输出。
8. 提交代码后，以最终 HEAD 生成源码包：

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\create-source-handoff.ps1 -KeepDirectory
~~~

9. 检查 SOURCE_HANDOFF_MANIFEST.json 的 gitCommit 与最终 HEAD 一致。
10. 只有老板明确授权才执行 git push origin main；默认不打 tag、不创建 GitHub Release。

## 2. 源码接手安装

最低要求：Windows 10/11、Node.js 22.5+、Git、PowerShell、TIA Portal/Openness 与 MCP 大版本匹配。客户第一次接手：

~~~powershell
Copy-Item .env.example .env
# 编辑 .env：填写客户自己的 JWT_SECRET、ADMIN_KEY、AI Key 和邮件配置
npm ci
npm test
npm start
~~~

需要 AI 才配置 AI Key；只做本地 TIA 诊断时可暂不配置 AI。不要把 .env 复制进源码 ZIP，不要把客户 Key 提交 Git。

## 3. 客户 Key 和账户配置

- JWT_SECRET：客户随机生成的长字符串，不能复用发行方值。
- ADMIN_KEY：客户管理员自定义密钥，不能放网页、截图或群聊。
- DeepSeek/K3/兼容网关：在设置页输入客户自己的 Key，保存后测试模型。
- SMTP/IMAP：如需邮件审批，使用客户自己的邮箱和授权码；不使用发行方邮箱授权码。
- 数据库中的供应商 Key 由 JWT_SECRET 派生加密；更换 JWT_SECRET 前先按升级手册处理，否则既有加密配置可能无法解密。

## 4. TIA/Openness 配置

1. 安装与 MCP runtime 相同主版本的 TIA Portal Openness；当前交付运行资产为 V21。
2. 确认存在 Siemens.Engineering.Base.dll 和完整 PublicAPI 目录。
3. 把运行账号加入 Siemens TIA Openness Windows 用户组；加组后注销并重新登录。
4. 在 TIA Portal 打开目标工程，关闭无关自动化客户端和模态对话框。
5. 如果 TIA AllowList 要求登记客户端，登记客户机解压目录中的实际 TiaMcpServer.exe；复制到另一台机器后路径改变，原路径登记不会自动迁移。
6. 运行 tools/diagnose-tia.ps1；它只输出脱敏环境状态，不读取 .env、数据库、Key 或日志正文。
7. 先通过只读 tia doctor、Connect、software-tree，再做变量表、硬件目录和写入。

Node 客户端路径探测顺序：YIN_TIA_PORTAL_ROOT、TiaPortalLocation、TIA_Opns、EditionMain、Openness PublicAPI 中的 Siemens.Engineering.Base.dll 反推、默认 Program Files 扫描。显式路径必须是真实 Portal 根目录且与 MCP 大版本一致。

## 5. 绿色包部署

1. 从可信来源取得 ZIP，先核对 SHA256。
2. 完整解压到本地可写目录，例如 D:\LaoyinPLC；不要在压缩包内直接运行，不要只复制 runtime 或 app 子目录。
3. 至少确认以下文件存在：

~~~text
老殷工控PLC助手.exe
runtime\laoyin-server.exe
app\engine\tia-mcp\runtime\v21\TiaMcpServer.exe
app\tools\diagnose-tia.ps1
说明文档\
~~~

4. 双击 老殷工控PLC助手.exe。启动器拉起服务、等待健康接口并打开浏览器；关闭时通过退出钩子回收 Node/MCP/EngineerYin 子进程。
5. 首次运行会在用户目录创建 60 天试用授权和运行目录；授权文件不在程序目录，复制绿色包不会复制发行方授权。
6. 在设置页录入客户自己的 AI/API Key，登录后按顺序连接 TIA、读取软件树、变量表、硬件搜索，再做小范围预检和确认写入。

绿色包排除 .git、开发 node_modules、测试快照、work/logs、work/db-backups、诊断缓存、源码入口和 package.json；外置 PS/TIA 资产必须保持相对目录结构。

## 6. 客户验收顺序

### 6.1 服务和许可

- 启动器能打开浏览器登录页。
- GET /api/license 返回 ok:true。
- 试用状态显示约 60 天；授权文件位于用户目录而非程序目录。
- 删除或篡改授权文件后，源码直跑和 SEA 均应拒启动、退出码 78，且 stderr 不含绝对路径、at 堆栈、node:internal 或内部错误常量。

### 6.2 环境和只读 TIA

- 登录后 /api/env-check 包含 healthScore 和 issues。
- /api/tia/mcp/status 未登录时应为 401/403，登录后不是 404。
- 连接博途、软件树、变量表、SearchHardwareCatalog 均有响应。
- TIA 版本、用户组、工程打开状态和 AllowList 均记录。

### 6.3 写入安全链

- 预检先给事实摘要和风险提示。
- 写入/回滚/下载/建工程/危险工具触发确认，确认 token 只消费一次。
- 编译失败显示目标与归因，不显示服务器内部路径。
- 不以“接口返回成功”代替现场工程核对；验收记录目标工程、块名和编译结果。

## 7. 故障处理与证据

先保留绿色包 SHA256、Windows 版本、TIA 主版本、MCP 文件版本和诊断报告；再阅读 TIA_Openness故障排查.md。发送给维护者的内容只包括脱敏诊断 JSON/TXT、错误摘要和时间，不发送 .env、数据库、授权文件或完整日志。

- 页面打不开：检查端口 3000、旧服务进程、启动器和完整解压目录。
- MCP 404：优先重启陈旧服务，确认 /api/tia/mcp 先挂。
- Openness 失败：先检查大版本、PublicAPI DLL、用户组、AllowList 和工程是否打开。
- 变量表空：可能是当前工程确实没有 PLC tags，不应凭空判为后端故障。
- 写入失败：保留预检事实和编译归因，不重复点击，不绕过安全链。

## 8. 升级、备份、回滚

升级前保存旧绿色 ZIP 哈希和用户目录；程序启动时会备份 plc_assistant.db 到 work/db-backups，并保留最近 7 份。新包先在副目录干净解压验证，再替换旧程序目录。不要覆盖用户目录授权文件。失败时停止启动器，保留诊断证据，恢复旧目录和数据库备份，确认旧哈希后重启。

## 9. GitHub 和源码 ZIP

GitHub 只放不含真实凭据的源码与文档。tools/create-source-handoff.ps1 使用 git archive HEAD，并排除 .env、数据库、授权、日志、截图、ZIP 和 node_modules。发布前执行：

~~~powershell
git status --short
git ls-files | Select-String -Pattern '\.env$|plc_assistant\.db|work/logs|db-backups'
~~~

第二条不应匹配真实敏感文件。README、.env.example 和文档中的配置说明可以存在，但不能出现真实值。

## 在线更新

### 客户使用
1. 启动绿色包后，右击任务栏托盘图标，选择“检查更新”。
2. 有新版时确认下载；软件会校验 HTTPS 清单、包体大小和 SHA256，再关闭旧进程、替换并健康检查。
3. 更新成功自动启动新版；失败时保留或恢复原版本，客户数据与授权不被覆盖。
4. GitHub 清单或网络暂时不可用时只显示中文提示“当前无法检查更新，请稍后重试”，不会显示 GitHub 404，也不影响当前版本使用。

### 作者发布
每次发布必须按顺序：构建 LaoyinPLC-Green-v<版本>.zip → 计算 SHA256 和字节数 → 更新仓库根目录 update-manifest.json 的 version/packageUrl/sha256/sizeBytes → 同一提交推送源码、ZIP、清单 → 用浏览器或 Invoke-WebRequest 验证两个 Raw HTTPS 地址均返回 200。未完成这四步，客户检查更新会提示暂不可用。

### 数据保护
在线更新只替换程序目录，不覆盖 %LOCALAPPDATA%\老殷工控PLC助手 下的 license.json、trial.marker、plc_assistant.db 及客户个人 API Key。
