# 老殷工控 PLC 助手：源码交接说明

## 交接目标

本交接包用于客户或维护团队在自己的 Windows 机器上复现、开发和诊断老殷工控 PLC 助手。包内不包含发行方的 API Key、SMTP 授权码、JWT 私钥/生产密钥、数据库、授权文件、运行日志或用户数据。

GitHub 仓库是版本源；源码包由 `tools/create-source-handoff.ps1` 按当前 Git 版本生成，生成时会再次排除敏感和运行时文件。

## 开发语言与技术栈

- 后端：JavaScript / Node.js 22.5+。
- Web 服务：Express 4；前端：HTML5、CSS3、原生 JavaScript，无前端构建框架。
- 数据：Node.js SQLite 封装，数据库仅保存在本机用户/运行目录。
- PLC 工程引擎：PowerShell 5.1/7 脚本、EngineerYin 规则与 TIA Portal Openness。
- MCP：C#/.NET Framework 4.8，TIA MCP 通过 stdio JSON-RPC 连接。
- 绿色启动器：C# WinForms/.NET Framework；后端另有 Node SEA 单文件运行版。
- 安全：JWT、本地访问限制、AES-256-GCM API Key 加密、写入/下载/危险工具三级确认。

## 源码启动

```powershell
npm ci
Copy-Item .env.example .env
# 用编辑器填写自己的配置；不要把 .env 提交或发送给他人
npm test
npm start
```

浏览器访问 `http://localhost:3000`。源码模式需要本机 Node.js；绿色版不需要客户安装 Node.js。

## 客户自己的 API Key

1. 复制 `.env.example` 为 `.env`，或直接在登录后打开“设置”。
2. 填入客户自己的 API 地址、协议类型、模型和 API Key。
3. Key 只由当前用户本地加密保存；不要把 `.env`、数据库和 `%LOCALAPPDATA%\老殷工控PLC助手` 目录发给其他客户。
4. 如果接入 SMTP，SMTP 用户名和授权码也必须由客户自己配置。
5. 本项目不提供发行方 Key，也不会从 GitHub、绿色包或诊断报告恢复 Key。

## TIA 连接的必要条件

- Windows 10/11 x64。
- 已安装与 MCP 运行时匹配的 TIA Portal。本版本绿色运行包内置 V21 MCP，客户必须安装 TIA Portal V21，并启用 Openness/PublicAPI。
- 当前 Windows 用户在本地组 `Siemens TIA Openness` 中；添加后注销/重新登录 Windows。
- TIA 工程已经在 TIA Portal 中打开，且 Openness 允许当前客户端。
- 绿色包必须完整解压，不能只复制 `runtime` 或 `app` 子目录。
- `app\engine\tia-mcp\runtime\v21\TiaMcpServer.exe` 及其旁边 DLL 必须完整存在。

## 路径兼容修复

Node 客户端现在按以下顺序发现 TIA 根目录：

1. `YIN_TIA_PORTAL_ROOT` 环境变量；
2. `TiaPortalLocation` 环境变量；
3. `_InstalledSW\TIAPxx\EditionMain`；
4. `_InstalledSW\TIAPxx\TIA_Opns`；
5. `Openness\xx.0\PublicAPI\...\net48` 中 `Siemens.Engineering.Base` 反推；
6. `Program Files\Siemens\Automation\Portal Vxx` 默认目录。

这修复了“已安装 Openness，但没有可选的 `TIA_Opns` 注册表子键，直接启动 MCP 失败”的常见情况。V21 MCP 不会冒充 V18/V19/V20；其他大版本必须提供对应版本的 MCP 运行时并由维护者重新构建验证。

## 诊断

源码仓库运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\diagnose-tia.ps1
```

绿色包中若随包提供该脚本，从 `app` 目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\diagnose-tia.ps1 -AppRoot .
```

报告输出到 `work\diagnostics\`，包含脱敏的环境状态、TIA/Openness、MCP 文件完整性、端口 3000 和只读 `tia doctor` 结果。报告不读取 `.env`、数据库、日志正文或密钥。交给管理员时只发送同一时间生成的 `.json` 和 `.txt`。

## 从零接手的完整路线

### 第 0 天：安全隔离

- 只接收源码 ZIP/绿色 ZIP 和 SHA256，不接收发行方 `.env`、数据库、授权文件、日志或用户目录；
- 在隔离目录解压并核对 manifest commit；
- 创建客户自己的 `.env`，重新生成 JWT_SECRET/ADMIN_KEY；
- 确认 Git 工作区没有把 `.env`、数据库或 Key 加入暂存区。

### 第 1 天：源码可复现

- 安装 Node.js 22.5+、Git、PowerShell；执行 `npm ci`、`npm test`；
- 阅读 `server.js`、`lib/auth.js`、`routes/tia.js`、`routes/tia-mcp.js`、`tia-mcp-client.js`、`engineer-yin-bridge.js` 和 `lib/tia-queue.js`；
- 先只启动服务和登录页，不连接 TIA；确认 `/api/license`、`/api/env-check` 和静态敏感文件拦截；
- 运行脱敏 `tools/diagnose-tia.ps1` 并保存报告。

### 第 2 天：只读 TIA

- 安装匹配主版本 TIA/Openness；加入 Openness Windows 组并重新登录；
- 打开一个非生产测试工程；确认 AllowList；
- 先跑 `tia doctor`、Connect、软件树、变量表、硬件目录；
- 只读路径通过后，才进入写入/编译验收。

### 修改代码的强制顺序

1. 先写/更新测试，明确成功、拒绝、超时、崩溃重启和回退分支；
2. 再改最小范围代码；
3. 复跑 `npm test`、`git diff --check` 和敏感扫描；
4. TIA 实测必须分开记录“仿真/单测”和“真实工程”；
5. 独立审计通过前，不把“本地能启动”写成“客户现场已通过”。

## 真实限制与责任边界

- 本交付当前内置并验证的是 TIA V21 MCP；V18/V19/V20 需要对应 runtime 和单独验证；
- Node 客户端已增加 `EditionMain`、Openness PublicAPI、显式环境变量和默认目录回退；
- TIA MCP C# 源码同步增加路径回退，但本机若缺 .NET Framework 4.8 Developer/Targeting Pack，不能声称已重新编译 runtime；
- 绿色包不能替代客户本机 TIA Portal、Openness、许可证、Windows 组或 AllowList；
- 绿色包复制后，客户的 API Key、数据库和 60 天授权状态不会从发行方机器复制过去；
- 源码完整交接意味着客户可以修改离线授权逻辑；如果这不符合商业要求，必须使用签名许可证或在线授权服务，而不是依赖隐藏源码。
