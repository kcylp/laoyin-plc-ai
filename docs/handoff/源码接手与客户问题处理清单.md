# 源码接手与客户问题处理清单

> 这是一张可直接交给客户技术负责人、现场工程师和后续维护者的操作清单。每一项都要记录结果；“未执行”不能写成“通过”。

## A. 收到源码当天

- [ ] 核对源码 ZIP SHA256 与 SOURCE_HANDOFF_MANIFEST.json 的 gitCommit。
- [ ] 阅读《完整技术交接手册》《API路由与安全边界参考》《构建发布与客户部署手册》《TIA_Openness故障排查》。
- [ ] 确认未收到 .env、数据库、license.json、日志正文或发行方 Key。
- [ ] 安装 Node.js 22.5+、Git、PowerShell，执行 npm ci 和 npm test。
- [ ] Copy-Item .env.example .env；生成新的随机 JWT_SECRET、ADMIN_KEY。
- [ ] 使用客户自己的 AI、SMTP/IMAP 凭据，不复用发行方账号。
- [ ] 记录 Git HEAD、Node、Windows、TIA 和 MCP 主版本。

## B. 接入 TIA 前

- [ ] TIA Portal 主版本与 engine/tia-mcp/runtime/vXX 一致；本交付默认 V21。
- [ ] 安装 Openness/PublicAPI，能找到 Siemens.Engineering.Base.dll。
- [ ] 当前 Windows 用户加入 Siemens TIA Openness 组，之后注销/登录。
- [ ] TIA 已打开待操作工程，未被其他自动化客户端占用，未弹模态窗口。
- [ ] TIA AllowList 已登记客户机上解压后的实际 TiaMcpServer.exe。
- [ ] 运行 tools/diagnose-tia.ps1，保存脱敏 JSON/TXT。
- [ ] 先通过只读 tia doctor、Connect、software-tree，再验证变量表和硬件搜索。

## C. 修改 TIA 代码前

- [ ] 阅读目标模块、相关测试和安全链路。
- [ ] 不改 BOM、CTU_INT、S7DCL MLC、全局互斥队列、三级确认和主聊天区。
- [ ] 不把 confirmed:true 当作唯一授权，不删除后端预检或一次性 token 消费。
- [ ] 新 TIA 路由同时保留 JWT 与 localOnly。
- [ ] 不让 MCP/PowerShell 无超时、无限并发或缺少退出清理。
- [ ] 修改 C# 前确认 .NET Framework 4.8 targeting pack；缺失时如实记录 runtime 未重编译。
- [ ] 为成功、拒绝、超时、重启、回退和路径探测增加可复现测试。

## D. 绿色包发布前

- [ ] 包从最终提交重新构建，不从旧 stage 手工拷贝。
- [ ] 包含启动器、SEA 服务、TIA MCP、EngineerYin、诊断脚本和说明文档。
- [ ] 不含 .git、开发 node_modules、.env、数据库、授权、日志、截图、诊断缓存和旧 ZIP。
- [ ] 端口 3000 空闲时执行 clean-profile；若占用只记录 SKIP，不能伪造 PASS。
- [ ] 篡改/删除授权应退出码 78；stderr 无绝对路径、at 、node:internal、LICENSE_REQUIRED 或 Error 头。
- [ ] TiaMcpServer.exe 与必要 DLL 存在；记录关键文件 SHA256。
- [ ] 记录冷启动耗时、ZIP 字节数、ZIP SHA256、构建时间和验证输出。

## E. 页面打不开

1. 确认启动器是否运行、浏览器地址是否是实际 PORT。
2. 检查 3000 是否被旧 Node/其他程序占用；不要强杀不明系统进程。
3. 确认完整解压目录含 runtime/laoyin-server.exe、app 和 app/tools。
4. 先请求 /api/license；能返回再开登录页。
5. 若出现旧路由 404，先重启陈旧服务进程，再复测；不要立即改代码。
6. 发送启动器版本、ZIP SHA256 和不含敏感信息的错误摘要。

## F. Openness 接不上

1. 先运行诊断脚本，不要先改注册表。
2. 确认 TIA/Openness 与 MCP 主版本一致；V21 不能连 V20/V19/V18 runtime。
3. 确认 Siemens.Engineering.Base.dll 和 runtime DLL 完整。
4. 检查 Windows Openness 组；加组后注销/登录。
5. 检查 AllowList 是否登记了复制后新目录的 MCP EXE。
6. 确认 TIA 已打开工程且没有模态对话框。
7. 路径探测失败时设置 YIN_TIA_PORTAL_ROOT 为真实 Portal 根目录，重启应用；不要指向 PublicAPI/net48 子目录。
8. doctor 成功后再测软件树、变量表、硬件搜索。
9. 交给维护者：Windows/TIA/MCP 版本、包哈希、脱敏诊断 JSON/TXT；不要发 .env、DB、授权或完整日志。

## G. 写入/编译/下载失败

- 回到只读 Connect/software-tree，确认连接稳定。
- 保存预检事实、确认时间和编译归因，不重复点击造成并发。
- 检查 XML/SCL/STL 完整性、BOM、块声明、CTU_INT 和 S7DCL MLC 规则。
- 不为了“让它过”删除规则、互斥队列或确认机制。
- 确认目标工程可写且未被别的客户端占用；失败后重新读取软件树。
- 只交错误摘要；服务日志留在客户机，按隐私政策处理。

## H. 安全事件

- Key、授权或数据库误入提交/ZIP：立即停止外发，撤销并轮换凭据；仅删工作区文件不能清除 Git 历史。
- ADMIN_KEY/JWT 泄露：更换客户配置、注销旧 token，检查管理员操作和 TIA 日志。
- 发现 TIA 可被非本机访问：立即停止服务，恢复 localOnly，检查防火墙/代理。
- 发现写入绕过确认：停止生产使用，保留证据，先修复再独立审计。

## I. 升级和回滚

- [ ] 记录新旧 SHA、变更文件、测试数字和限制。
- [ ] 源码 ZIP 与绿色 ZIP 来自同一最终 HEAD，或明确差异。
- [ ] 现场实测、单测、模拟验证分开记录。
- [ ] 升级前核对 ZIP SHA256；新包先在副目录冷启动。
- [ ] 回滚时停止启动器、保留诊断证据、恢复旧目录和数据库备份。
- [ ] 只有老板明确授权才 push；不擅自打 tag 或 GitHub Release。
- [ ] 牢记：源码完整交接意味着离线授权逻辑可被源码接收者修改。
