# 老殷工控 PLC 助手完整技术交接手册

> 本文是源码、绿色版、TIA Openness、运维和安全的总交接入口。“毫无保留”指完整交代架构、实现、配置、构建、排错、限制和维护红线；不包含任何真实 API Key、SMTP/IMAP 授权码、JWT 生产密钥、客户数据库、授权文件、日志或用户数据。版本身份以源码包根目录 `SOURCE_HANDOFF_MANIFEST.json` 的 `gitCommit` 为准。

## 1. 产品定位与能力边界

老殷工控 PLC 助手是运行在 Windows 本机的西门子 PLC 工程工作台。浏览器负责交互，Node.js/Express 负责账号、AI 代理、写入安全链、历史和引擎编排，PowerShell EngineerYin 与 C# TIA MCP 通过 Siemens TIA Portal Openness 操作本机已打开的工程。

主要能力：

- 注册、登录、可选管理员审批和邮件审批；
- 每用户独立配置 AI 供应商、协议、模型与 API Key；
- S7-200 SMART、S7-1200、S7-1500 上下文；
- LAD、FBD、SCL、STL、GRAPH 提示、校验和代码动作；
- XML/LAD/FBD 预检、写入、编译、历史快照与回滚；
- SCL/STL ExternalSources 写入；
- S7DCL 导入、导出及 MLC/编译诊断；
- TIA 连接、软件树、块描述、变量表、实时读值和下载；
- 硬件目录搜索、设备添加、HMI Unified 工具和快速建工程；
- TIA 操作 JSONL 日志、数据库启动备份、环境健康分；
- 绿色免安装启动器、60 天离线试用和脱敏诊断。

能力边界：

- 绿色包不会安装 TIA Portal，也不能复制 Siemens Openness 组件代替正式安装；
- 当前随包 MCP runtime 面向 TIA Portal V21。V18/V19/V20 需要对应 runtime 与重新验证；
- TIA Openness 只能操作本机实例，所以关键 TIA 路由限定 localhost；
- AI 依赖客户自己的兼容 API，交付物不提供发行方 Key；
- 离线授权用于阻止普通复制重置，不是硬件加密狗。拿到完整源码的人可以修改授权代码，“完整交源码”和“源码接收者绝对无法绕过授权”不能同时成立。

## 3. 总体架构

```text
浏览器
  │ HTTP/SSE + JWT
  ▼
Express server.js ── SQLite / 客户 AI API
  │
  └─ lib/tia-queue.js 全局互斥队列
       ├─ engineer-yin-bridge.js
       │    ├─ yin_worker.ps1 ─┐
       │    └─ yin_import.ps1 ─┴─ YinImportCore.ps1 公共逻辑
       └─ tia-mcp-client.js ─ TiaMcpServer.exe ─ TIA Portal Openness
```

固定原则：

1. `server.js` 只组装服务，不重复实现路由；
2. 所有驱动 TIA 的操作共享 `lib/tia-queue.js`；
3. worker 与旧脚本共同 dot-source `YinImportCore.ps1`，规则只有一份；
4. MCP 优先挂接用户已经打开的主工程；
5. 写入经过预检、事实展示、一次性确认令牌和编译；
6. 危险 MCP 工具必须显式 `confirmed:true`；
7. `/api/tia/mcp` 必须先于 `/api/tia` 挂载。

## 5. 启动链路

源码模式：

1. `node server.js`，dotenv 读取项目根 `.env`；
2. `ensureLicense()` 校验或创建当前 Windows 用户的试用记录；
3. 失败时 `process.exit(78)`，不抛异常；
4. 打开 SQLite，初始化 AI 层；
5. 安装启动器退出端点；
6. 在静态资源之前拦截敏感文件；
7. 挂载 auth、chat、AI、admin、legacy validate、TIA MCP、TIA；
8. 启动监听、数据库备份；
9. 3 秒后预热 MCP 与 Yin worker；
10. 审批模式和邮件凭据齐全时启动邮件监听。

绿色模式：

1. 双击 `老殷工控PLC助手.exe`；
2. 检查 `runtime/laoyin-server.exe` 与 `app/`；
3. 端口 3000 被占用时中文提示；
4. 创建 `%LOCALAPPDATA%\老殷工控PLC助手` 和 `app/work` 子目录；
5. 生成随机 `LAUNCHER_SHUTDOWN_TOKEN`；
6. 设置 `APP_ROOT`、`DB_PATH`、`PORT` 后隐藏启动 SEA；
7. 最多 30 秒轮询 `/api/license`；
8. 成功后打开浏览器并驻留托盘；
9. 托盘退出调用 `/api/system/shutdown`，超时才杀进程树。

## 6. 静态资源与错误处理

`server.js` 在 `express.static` 前拒绝 .env、数据库、日志、Markdown/TXT、Node 源码入口、包描述和 node_modules。HTML/JS/CSS 使用 no-store，现场升级后浏览器不会继续执行旧文件。

全局 500 响应统一为：

```json
{"success":false,"message":"服务器内部错误"}
```

404 统一为“页面未找到”。服务响应不得返回内部堆栈或绝对路径。

## 7. 数据库和数据生命周期

源码默认 DB 是项目根 `plc_assistant.db`。绿色启动器设置为：

`%LOCALAPPDATA%\老殷工控PLC助手\plc_assistant.db`

表：

- `users`：用户名、bcrypt 密码哈希、邮箱、状态；
- `ai_providers`：用户、Base URL、加密 Key、协议、测试状态；
- `ai_models`：模型、标签、上下文、启用和测试状态；
- `user_settings`：当前模型；
- `tia_write_history`：写入快照，每用户每块保留最近 30 条。

启动时备份到 `<APP_ROOT>/work/db-backups/plc_assistant.YYYY-MM-DD.db`，只保留最近 7 份。数据库包含用户数据、加密 Key 和代码快照，不得外发。

## 8. 认证、管理员和 Key

- 密码使用 bcrypt，成本 10；
- JWT 从 Authorization Bearer 读取；
- 默认注册免审批，只有 `REGISTRATION_APPROVAL_REQUIRED=true` 才 pending；
- 管理页用请求体 `adminKey` 比较 `ADMIN_KEY`；
- 源码存在开发回退值，客户必须用自己的环境值覆盖；公开源码中的默认值不能当秘密。

AI Key：

- 每用户独立；
- AES-256-GCM；
- 密钥由 `JWT_SECRET` SHA-256 派生；
- 数据库存储 IV、AuthTag、Ciphertext；
- 列表只给掩码；
- 明文查看接口要求 JWT + localhost；
- 更换 `JWT_SECRET` 会导致旧数据库 Key 无法解密；
- 复制程序目录不会复制 Key，复制用户数据目录会，禁止连用户目录一起交付。

## 9. 60 天离线授权

位置：

```text
%LOCALAPPDATA%\老殷工控PLC助手\
├─ license.json
└─ trial.marker
```

首次运行以排他创建方式同时生成 marker 和 license。下列情况拒绝启动：license 删除但 marker 存在、JSON/版本非法、机器指纹或签名不一致、日期非法、满 60 天。失败统一退出码 78，只输出一行中文，不含 `Error:`、`at ...`、`node:internal` 或路径。

离线签名盐位于程序和源码，无法抵抗拿到完整源码后主动改程序。商业级授权应使用发行方私钥签名、客户端只内置公钥，或在线授权服务。

## 11. EngineerYin 架构

`engineer-yin-bridge.js` 负责 engine 路径发现、按语言选 XSD、XML 片段提取、LAD 业务规则、输入类型识别、worker 调用和 legacy 回退。

`YIN_WORKER=0` 强制使用 `yin_import.ps1`。`yin_worker.ps1` 与 `yin_import.ps1` 都 dot-source `YinImportCore.ps1`。不得把 BOM、归因、编译或 S7DCL 规则复制成两套。

## 12. TIA MCP 客户端

`tia-mcp-client.js` 把 `TiaMcpServer.exe` 作为常驻子进程：newline-delimited JSON-RPC、initialize、请求 id、超时、pending map、崩溃后下次自动重启、进程退出时停止。`status()` 提供 available/running/ready/pending/project/portalRoot/TIA 主版本和近期 stderr 摘要。

默认 runtime：`engine/tia-mcp/runtime/v21/TiaMcpServer.exe`。

## 13. TIA 路径探测

顺序：

1. `YIN_TIA_PORTAL_ROOT`；
2. `TiaPortalLocation`；
3. `_InstalledSW\TIAPxx\EditionMain` 的 Path；
4. `_InstalledSW\TIAPxx\TIA_Opns` 的 Path；
5. `Openness\xx.0\PublicAPI\...\net48/net47` 中 Siemens.Engineering.Base 路径反推；
6. 扫描 `%ProgramFiles%\Siemens\Automation\Portal Vxx`；
7. 默认 Program Files 路径。

探测后显式传 `--tia-portal-location` 与 `--tia-major-version`。这修复客户机器缺少可选 `TIA_Opns` 子键的问题。

## 14. TIA 挂接与互斥队列

`mcpEnsureAttached()`：Connect → GetProject → 选 IsPrimary 或第一个 → AttachToOpenProject。所有 preflight/import/connect/call/scaffold/hardware/tag-table/export 进入同一个 `enqueueTiaOp()`。拆成多条队列会让 EngineerYin 与 MCP 同时驱动 TIA，引发 COM/Openness 冲突。

## 15. 写入安全链

普通写入：

1. `/api/tia/preflight` 检查结构、语言、业务规则；
2. 进入全局队列；
3. 返回项目、PLC、块名、覆盖等事实；
4. 后端签发 32 字节随机 token，绑定用户、XML SHA256、事实和 5 分钟有效期；
5. 前端展示统一确认；
6. `/api/tia/import` 必须同时有 `confirmed:true` 和 token；
7. 后端一次性删除 token，并核对用户、哈希和有效期；
8. 成功后记录历史和 JSONL 日志。

危险 MCP 工具名匹配 `download|delete|remove|force|stop|reset` 时，必须 `confirmed:true`。建工程第一次只预览/dry run，第二次确认才执行。

## 16. 四条写入通道和红线

- XML/LAD/FBD：XSD、FlgNet、LAD 规则、Wire Pin 修复、导入和编译；
- SCL：ExternalSources，保留实测 UTF-8 BOM 与归因；
- STL：ExternalSources，沿用相同预检/导入/编译链；
- S7DCL：MCP/S7DCL，保留 MLC、命名修正、重导入和诊断。

不可随意修改：BOM/编码、`CTU_INT`、S7DCL MLC、LAD 泛型边界、全局队列、一次性 token、三级确认、`plc-language.js`、`tia-confirmation.js`、`tia-import-state.js` 的安全语义。修改这些内容必须用真实 TIA 工程重新导入、编译并留证，不能只看源码断言。

## 17. 日志、历史和健康检查

TIA 操作日志：`<APP_ROOT>/work/logs/tia-ops.jsonl`，每行字段为 `ts/user/op/target/ms/ok/err`。日志可能包含用户名、块名和错误摘要，不进公开仓库或空白客户包。

`GET /api/env-check` 汇总 Openness 路径、用户组、EngineerYin、MCP、AI、邮件、`healthScore` 和 `issues[]`。它是引导摘要，不代替真实 MCP doctor。

## 19. 客户诊断

在绿色包 `app` 目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\diagnose-tia.ps1 -AppRoot .
```

跳过 doctor：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\diagnose-tia.ps1 -AppRoot . -SkipMcpDoctor
```

## 23. 绿色包构建

入口：`work/green-build/build-green.ps1`。流程是清 stage、webpack、SEA blob、复制 Node EXE、移除签名并注入 blob、复制 Web/engine/诊断、删除测试和日志、编译启动器、复制文档、纯度门禁、生成 ZIP。

当前构建机依赖路径包括：

- `D:/DevTools/nodejs/node.exe`；
- `work/sea-toolchain/node_modules`；
- Windows SDK SignTool；
- .NET Framework 64 位 `csc.exe`。

这些是构建依赖，不是客户运行依赖。迁移构建机时应参数化或自动探测。

历史 `package.json` 含 UTF-8 BOM。脚本只在 webpack 期间临时移除，finally 恢复原字节，构建不能永久改仓库文件。

## 27. 常见故障

页面打不开：检查 `/api/license`、端口 3000、启动日志和旧服务。新路由 404 但旧路由正常时，常见根因是旧进程没有重启。

接不上 Openness：核对主版本、PublicAPI DLL、用户组和注销重登、工程是否打开、AllowList、杀毒、非默认路径，再运行诊断。

变量表空：`success:true, connected:true, tables:[]` 表示当前挂接工程没有 PLC tag tables，不是路由失败。

AI 不工作：设置客户自己的供应商、Base URL、协议、Key，测试并保存至少一个模型，检查网络和额度。

## 29. 已知限制和安全债务

1. 离线授权不是不可破解 DRM；
2. 管理员是共享 ADMIN_KEY，不是 RBAC；
3. 开发回退 JWT/管理员值必须覆盖；
4. Key 加密依赖 JWT_SECRET，没有独立 KMS；
5. `/api/env-check` 是本机环境摘要，未来开放局域网要重审；
6. 前端 HTML/CSS/JS 必然能被浏览器查看，SEA 只隐藏后端源码入口；
7. 绿色构建脚本含构建机绝对工具路径；
8. C# runtime 尚未包含本轮 C# 回退重编译；
9. 默认端口固定 3000；
10. AllowList、用户组和版本兼容不能由绿色包绕过。

## 32. 交付物关系

GitHub 是版本源；源码 ZIP 是某个 commit 的净化快照；绿色 ZIP 是客户运行包；诊断 JSON/TXT 是某台机器的脱敏证据；交付报告记录改动、测试、哈希和限制。客户运行问题先拿绿色包 SHA256 与诊断报告，源码问题先拿 commit SHA，实机编译问题再核对测试工程和 TIA 版本。
