## 5.7　轴错误复位

**id** `mc-reset`
**用到的指令** `MC_Reset`

### 名称/别名
**中文**：轴错误复位 · 轴复位 · 清除轴故障 · 确认技术报警
**英文**：Axis Reset · MC_Reset · Acknowledge Technology Alarm

### 适用场景
轴出错（限位触发、跟随误差超限、驱动器故障、技术报警）后，确认并清除错误，使轴能重新使能与运动。

### 梯形图逻辑描述

```
Network 1: 复位许可（✅ 可生成）—— ⚠️ 必须串「故障已消失」
  常开[复位按钮] → PBox
      串联 常开[手动允许]                    ← 需方式判断，防运行中误触发
      串联 常闭[急停辅助动作]                ← 现行故障必须已消失
      串联 常闭[安全状态丢失]
      →  SCoil[轴复位Execute]
  常开[MC_Reset.Done] 并联 常开[MC_Reset.Error]
      →  RCoil[轴复位Execute]

Network 2: 【🔴 手工添加】MC_Reset
  Execute ← [轴复位Execute]
  Axis    ← 工艺对象
  （Restart 引脚：用于重新初始化工艺对象，谨慎使用）
  输出：Done / Busy / Error / ErrorID (/ErrorInfo：仅 1200)

Network 3: Done 捕获与报警清除（✅ 可生成）
  常开[MC_Reset.Done] → PBox
      →  RCoil[Alm_AxisPower]、RCoil[Alm_Idx]、RCoil[Alm_Jog]…
      →  Move(0) → [轴错误码]
      →  RCoil[已回零]                     ← ⚠️ 见下：限位/复位后位置基准可能已失效

Network 4: 复位超时（✅ 可生成）
  常开[MC_Reset.Busy]  →  T_RstTmo(IN)，PT = 复位超时
  常开[T_RstTmo.Q]     →  SCoil[Alm_ResetTmo]

Network 5: ⚠️ 限位恢复：必须反向退出（✅ 可生成的部分是"封锁禁止方向"）
  常开[撞下限位]  →  线圈[禁止负向]
  常开[撞上限位]  →  线圈[禁止正向]
  （点动/定位的方向请求必须串对应的常闭）
```

### 🔴 限位恢复的官方规则：`MC_Reset` 确认后必须**反向**退出

《权威参考》第六节明确：软限位（`16#8001`/`16#8002`）与硬限位（`16#8003`/`16#8004`）**两者都需 `MC_Reset` 确认后反向退出**。

**撞硬限位后朝禁止方向发指令** → **`16#800E` / `16#0042`** → **Remove enable**（掉使能）。

**→ 所以复位后必须在 PLC 侧封锁"朝限位方向"的运动请求**，否则操作工习惯性再按一下同方向，直接掉使能，要重新走一遍复位流程。

限位的错误反应（S7-1200 完整；S7-1500 **待核**）：

| ErrorID | 含义 | 错误反应 |
|---|---|---|
| `16#8001` / `16#8002` | 软限位下限/上限 | 默认 **`-`（不掉使能）**；只有 ErrorInfo `16#0010`「以急停减速度**越过**」才 Remove enable |
| `16#8003` / `16#8004` | 硬限位下限/上限 | 一律**急停减速度**停车；**PTO → 急停斜坡；PROFIdrive/模拟量 → 掉使能** |
| `16#800E` / `16#0042` | 撞硬限位后朝禁止方向发指令 | **Remove enable** |

限位属 "Operating error **WITH** axis stop"，官方定义：
> "The errors are indicated in **the error-triggering Motion Control instruction and in the Motion Control instruction "MC_Power"**."

### 参数与整定

| 参数 | 建议初值 | 依据 |
|---|---|---|
| 复位超时 | 3–10 s | 复位是快速操作；超时说明故障未消除或通信异常 |
| 复位后是否清 `已回零` | **建议清**（撞限位后位置基准通常已不可信；开环步进尤其） | 工程判断，**需老殷确认** |
| 退限位的点动速度 | 点动速度 × 0.3~0.5（更慢） | 退限位时机械已在极限位置，宜慢 |

### 常见坑　⚠️【待老殷审】

- 🔴 **复位不串「故障已消失」** → 按了没用，操作工以为按钮坏了。与 4.1 报警复位同理。
- 🔴 **复位不用边沿 / 不带方式判断** → 运行中误触发。总表明确要求「复位按钮不会在运行中误触发（需带方式判断）」。
- 🔴 **复位后不封锁"朝限位方向"** → 操作工习惯性再按同方向 → **`16#800E`/`16#0042` → 掉使能**，白复位一次。
- 🔴 **复位后不清 `已回零`** → 撞限位/丢步后位置基准已不可信，绝对定位会撞机。**建议复位后强制重新回零**（需老殷确认工程策略）。
- **把 `MC_Reset` 当"万能清故障"** → 它只确认轴的技术报警/错误。**驱动器侧的故障可能需要在驱动器上复位或断电重启。** 机械原因（卡死、断带）不消除，复位后立刻再报。
- **`Restart` 引脚随手用** → 它是**重新初始化工艺对象**，会中断一切、重载组态。**不是普通复位，不要在自动流程里用。**
- **复位后立刻发运动指令** → 需要稳定延时（见 5.1）。
- **`Done` 轮询漏采**（通用⑤a）→ 边沿捕获。
- **限位开关不是直接断开触点** → **安全相关的位置检测【标准强制】必须是直接断开触点**（IEC 60204-1:2016 **10.1.4**）。
- **不区分软限位与硬限位的行为** → 见上表。软限位默认不掉使能，硬限位在 PROFIdrive/模拟量下掉使能，PTO 下走急停斜坡。**处理流程不同。**
- **S7-1500 侧的限位编号照抄 1200** → **S7-1500 的 technology alarm 编号表定义在《S7-1500/S7-1500T Motion Control alarms and error IDs》分册，未下载，编号未核。**
  **唯一已确认的 S7-1500 编号是 alarm 541**（定位监视，在 Axis functions 分册正文里）。
  **→ 不推断，不照抄。** 这也是《权威参考》第七节列的"最该补的一条"。
- **报警不监视 `MC_Power.Error`** → 通用⑤(c)。
- **`ErrorInfo` 跨平台照抄** → S7-1500 无此输出。

### 上机前必须确认　⚠️【待老殷审】

- [ ] 复位条件**串了「故障已消失」**（实测：故障未消除时按复位，确认无效且有提示）
- [ ] 复位**用边沿 + 带方式判断**，运行中不会误触发（实测：自动运行中按复位）
- [ ] **复位后封锁"朝限位方向"的运动请求**（实测：撞限位 → 复位 → 试按同方向，确认被拦，不会掉使能）
- [ ] 复位后 `已回零` 的处理策略已确认（建议清除并强制重新回零），并实测
- [ ] `Restart` 引脚的使用已明确（**不在自动流程里用**）
- [ ] 复位后有**稳定延时**才允许发运动指令
- [ ] `Done` 用边沿捕获
- [ ] 限位开关（**安全相关的**）为**直接断开触点**器件　【标准强制 IEC 60204-1:2016 10.1.4】
- [ ] 软限位与硬限位的**错误反应已分别实测**（各方向都撞一次，记录停车方式与是否掉使能）
- [ ] **退限位流程已实测**（撞限位 → 复位 → 反向慢速退出 → 重新回零 → 恢复自动）并写进操作手册
- [ ] 若为 S7-1500：technology alarm 编号**未照抄 1200**，已从《alarms and error IDs》分册核对（或已标注为待补）
- [ ] 报警逻辑同时监视 `MC_Power.Error`
- [ ] 驱动器侧故障的复位方式已确认（有些需在驱动器上复位或断电）
- [ ] 使用**独立实例**

### 可生成性
**🔴 暂不可自动生成 —— 等 TASK-012A 实证，当前只可人工编写。**
✅ **可生成的部分**：复位许可（含"故障已消失"串联与方式判断）、边沿触发、Done 边沿捕获与报警批量清除（`RCoil`）、错误码清零（`Move`）、复位超时、**限位方向封锁逻辑**（`Contact`/`Coil` 串联，白名单内 —— 这一条能实际防住"复位后又掉使能"）。
