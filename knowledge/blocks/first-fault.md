## 4.3　首出故障记忆

**id** `first-fault`

### 名称/别名
**中文**：首出故障 · 第一故障 · 首出记忆 · 首发故障 · 故障溯源
**英文**：First-Fault Capture · First-Out Alarm · First Fault Memory · Root Alarm

### 适用场景
故障常常连锁触发：一个真故障导致一连串次生故障，报警屏上一片红，**看不出根因**。首出故障记忆就是抓住"**第一个**"报警，其余的不再抢占。这是排障效率的关键，且成本极低。

### 梯形图逻辑描述

**核心机制：一个"已捕获"标志把后续报警挡在门外。**

```
Network 1: 首出捕获窗口 —— 只在"尚未捕获"时开放
  常闭[首出已捕获]  →  线圈[允许捕获]

Network 2..n: 各路报警争抢（每路一个，按优先级从上到下排）
  常开[Alm_EStop]    串联 常开[允许捕获] → PBox → Move(1)  → [首出代码]，SCoil[首出已捕获]
  常开[Alm_OL]       串联 常开[允许捕获] → PBox → Move(2)  → [首出代码]，SCoil[首出已捕获]
  常开[Alm_VFD]      串联 常开[允许捕获] → PBox → Move(3)  → [首出代码]，SCoil[首出已捕获]
  常开[Alm_StepTmo]  串联 常开[允许捕获] → PBox → Move(4)  → [首出代码]，SCoil[首出已捕获]
      并 → Move([步号]) → [首出时的步号]      ← 强烈建议一起记
  …

Network n+1: 顺带记录现场快照（大幅提升排障效率）
  常开[首出已捕获] → PBox
      →  Move([步号])       → [快照_步号]
      →  Move([温度工程值]) → [快照_温度]
      →  Move([液位工程值]) → [快照_液位]
      →  Move([当前配方号]) → [快照_配方]

Network n+2: 复位（与报警复位同步，且必须人工）
  常开[复位沿] 串联 常闭[有报警]
      →  RCoil[首出已捕获]，Move(0) → [首出代码]
```

**⚠️ 关键点：`允许捕获` 必须在同一个扫描周期内对所有争抢者一致。**
由于 LAD 从上到下扫描，`SCoil[首出已捕获]` 一置位，**同一周期内后面的 network 就已经被挡住** —— 这正好实现了"按 network 顺序定优先级"。**这是 LAD 扫描顺序的一个正面利用，但也意味着 network 的排列顺序 = 优先级顺序，改动顺序会改变行为。必须在注释里写明。**

### 变量表

| 名称建议 | 数据类型 | 方向/存储区 | 说明 |
|---|---|---|---|
| `首出已捕获` / `FF_Latched` | Bool | DB | 门闩 |
| `允许捕获` / `FF_Arm` | Bool | M | = NOT 已捕获 |
| `首出代码` / `FF_Code` | **Int** | DB | 1..n 对应各路报警。**HMI 查表显示文本** |
| `首出时的步号` / `FF_Step` | Int | DB | |
| `快照_xxx` | 各类型 | DB | 现场快照（温度、液位、配方号、产量…） |
| `首出时间戳` / `FF_TimeStamp` | DTL | DB | 需读系统时间（`RD_SYS_T` **不在白名单**，🔴 手工） |
| 各 `Alm_xxx` | Bool | DB | 来自 4.1 |
| `捕获沿_n` / `FF_P_n` | Bool | **Static** / M | 每路一个**独占** M_BIT |

**首出代码用 Int + HMI 查表，不要在 PLC 里存文本** —— 改文本不用重新下装 PLC。

### 参数与整定

| 参数 | 值 | 依据 |
|---|---|---|
| 报警优先级顺序 | **视工艺定** —— 由 network 排列顺序决定 | 建议序：急停 > 安全类 > 电气保护（热保护/变频故障） > 传感器故障 > 流程超时 > 工艺越限。**需与甲方/老殷确认** |
| 快照记录项 | 视工艺定 —— 建议至少含步号、当前配方、关键模拟量 | 排障经验 |
| 首出保持性 | 建议**保持性 DB** | 断电后仍能查到上次首出，对"设备半夜停了没人看见"的场景很有用 |

### 常见坑　⚠️【待老殷审】

- 🔴 **不用边沿，直接用电平争抢** → 报警持续为真期间每周期都尝试写 `首出代码`，虽然被 `允许捕获` 挡住，但如果 `允许捕获` 的逻辑有一周期的间隙（比如复位瞬间），就会被后来的次生故障顶掉。**用 `PBox` 更稳。**
- 🔴 **`首出已捕获` 与 `首出代码` 用 `Coil` 写** → 每周期无条件赋值，锁不住。**必须 `SCoil` + `Move`（Move 由边沿门控）。**
- 🔴 **network 顺序被随手调整** → **优先级悄悄变了**，而且没人知道。
  → **必须在每个 network 的注释里写明"本 network 顺序即优先级第 N 位，调整顺序会改变首出判定"**。这是本积木最容易被后人破坏的地方。
- **复位时只清报警不清首出** → 下一次故障的首出还是上次那个，彻底失效。**复位必须同步清首出。**
- **复位时清了首出但报警还在** → 已存在的报警会立刻重新抢占首出，看起来"复位没用"。**复位条件必须串「有报警已消失」**（与 4.1 同理）。
- **首出不放保持性** → 断电就没了。夜里设备停机、早上来看时啥都没有。**建议放保持性 DB。**
- **首出代码与 HMI 文本表不同步** → 显示错误的故障名，**比不显示更糟**（会误导排障方向）。**代码表必须在交付文档里列出，且与 HMI 一致。**
- **边沿 M_BIT 复用** → 见 1.6。每路一个独占位，FB 里放 Static。官方原文："you should use a **unique bit** for each edge instruction, and you should not use this bit any other place in your program."
- **没有快照** → 只知道"是热保护先跳的"，不知道当时在哪一步、什么配方、温度多少。**快照几乎零成本，收益极大。**
- **时间戳需要系统时间** → `RD_SYS_T` 等系统块**不在《技术底座》白名单**（零实例、未验证）→ 🔴 时间戳部分**当前只可人工添加**。
- **优先级排序不合理** → 把"工艺越限"排在"急停"前面，急停时首出显示的是工艺报警。**优先级必须由懂工艺的人定，不是 AI 定。**
- **首出代码用 Byte** → 报警超过 255 路时不够（虽罕见），且与 Int 比较时类型不匹配。**用 Int。**

### 上机前必须确认　⚠️【待老殷审】

- [ ] **报警优先级顺序已由老殷/甲方确认**，并与 network 排列顺序一致
- [ ] **每个 network 的注释里写明了"顺序即优先级"**，警告后人不要随手调整顺序
- [ ] 首出捕获**用边沿 + SCoil**，不用 Coil（实测：报警持续期间首出不被顶掉）
- [ ] **复位同步清首出**，且复位条件串了「报警已消失」（实测：故障未消除时复位无效）
- [ ] 首出在**保持性 DB**（断电重启实测：还能查到上次首出）
- [ ] **首出代码表已列入交付文档**，且与 HMI 显示文本**逐条核对一致**
- [ ] 快照项已确定并实现（至少含步号、配方号、关键模拟量）
- [ ] 各路边沿 M_BIT **独占**（F11 逐个查），FB 内放 Static
- [ ] 首出代码类型为 Int，路数上限有余量
- [ ] **实测验证过连锁故障场景**：人为制造一个会引发多个次生报警的故障，确认首出抓的是根因那一个
- [ ] 若需时间戳：确认是人工添加（系统时间读取块不在白名单）

# 五、运动控制

本类 7 条，**全部 🔴 —— 等 TASK-012A 实证，当前只可人工编写。**

### 为什么全是 🔴（说清楚，别让人误解成"我们不懂运动控制"）

这 7 条都是**带背景 DB 的 FB 调用**，而《技术底座》第三节确认：全项目 **`<Call>` 零实例、MC_\* 零实例、工艺对象引用语法未知**。
**→ 不能生成可导入的 XML。这是 XML 写法的缺口，不是知识的缺口。**

**知识侧我们是有货的**：《知识库_运动控制MC指令权威参考》是官方手册逐字摘录（🥈），用 `pdftotext -table` 提取（**不是** `-layout` —— 后者会把 ErrorID 单元格错配到相邻行，导致 `16#8406`/`16#8407` 归属反掉，研究中实际踩过并纠正）。
**所以本类每条积木的「手工添加指引」质量可以超过竞品** —— 竞品只是把块生成出来，不会告诉用户「你这个 Velocity 传负数在 1200 上会被拒」。

**适用上界**：S7-1200 Motion Control **V8.0**（TIA V17+，08/2024 手册）· S7-1500 Motion Control **V8**（TIA V20）。
**不覆盖**：Motion Control **V9** / **TIA V21** 新增部分 / **S7-1200 G2**（另一套硬件，需单独调研）。
