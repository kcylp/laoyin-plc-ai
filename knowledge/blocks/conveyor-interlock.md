## 2.4　输送线联锁启停

**id** `conveyor-interlock`

### 名称/别名
**中文**：输送线联锁 · 顺启逆停 · 顺序启动逆序停止 · 输送带联锁 · 级联启停
**英文**：Conveyor Interlock · Sequential Start / Reverse Stop · Cascaded Conveyor Control

### 适用场景
多段输送机串联。**启动必须从末段往前段（顺料流反方向）依次启，停止必须从首段往末段依次停** —— 目的是**任何时刻都不许把料堆在停着的下游段上**。

### 梯形图逻辑描述

设料流方向为 `C1 → C2 → C3`（C1 上料端，C3 卸料端）。

```
Network 1: 末段 C3 先启（它没有下游）
  (常开[启动请求] 并联 常开[C3运行]) 串联 常开[停止信号] 串联 常开[C3可用]
      →  线圈[C3运行]

Network 2: C2 —— 必须 C3 已运行才允许启
  (常开[启动请求] 并联 常开[C2运行])
      串联 常开[C3运行]                ← 下游已运行是启动前提
      串联 常开[停止信号] 串联 常开[C2可用]
      →  线圈[C2运行]

Network 3: C1 —— 必须 C2 已运行
  (常开[启动请求] 并联 常开[C1运行])
      串联 常开[C2运行]
      串联 常开[停止信号] 串联 常开[C1可用]
      →  线圈[C1运行]

Network 4: 停止（逆序）—— 停止请求先停 C1
  常开[停止请求] → RCoil[C1运行]
Network 5: C1 停稳（延时或零速检测）后才停 C2
  常闭[C1运行] → T_C1Clr(IN)，PT = 清料时间
  常开[T_C1Clr.Q] → RCoil[C2运行]
Network 6: 同理 C2 停稳后停 C3
  常闭[C2运行] → T_C2Clr(IN)，PT = 清料时间
  常开[T_C2Clr.Q] → RCoil[C3运行]

Network 7: 任一段故障 → 该段及其所有上游立即停（下游继续跑完清料）
  常开[C2故障] → RCoil[C2运行]、RCoil[C1运行]
```

**核心两条规则**
1. **启动：从下游往上游。** 每段的启动条件里串「下游段已运行」。
2. **停止 / 故障：从上游往下游。** 某段故障 → 它和它的**全部上游**立即停；**下游继续运行清料**（否则料堆在故障段上）。

| 名称建议 | 数据类型 | 方向/存储区 | 说明 |

### 参数与整定

| 参数 | 建议初值 | 依据 |
|---|---|---|
| **清料时间**（某段停后到停上游/下游的间隔） | **视工艺定** —— 由「带长 ÷ 带速」算 | 物理：料从入料点走到出料端所需时间。**这是可算的**：`t = 带长(m) ÷ 带速(m/s)`，取 1.2–1.5 倍余量 |
| 启动级间延时 | 1–3 s（或用「下游已达速」信号代替延时） | 给下游建立稳定运行的时间。**有零速/测速信号时优先用信号，不用延时** |
| 零速检测超时 | 启动后 3–10 s | 带速建立时间，需实测 |
| 打滑判据 | 视设备定 | 与测速轮安装、带速相关 |

**清料时间是可算的，不要靠猜**：`清料时间 = 该段有效带长 ÷ 实际带速 × 1.2~1.5`。带速要**实测**（在带上做记号，掐表量），铭牌值与实际常有偏差（负载、变频输出频率）。

### 常见坑　⚠️【待老殷审】

- **启动顺序搞反**（从上游先启）→ 料送到停着的下游段上，**堆料、埋带、撕带**。这是输送线的头号事故。
- **停止不逆序**（下游先停）→ 同上堆料。
- **某段故障时把下游也立即停** → 料堆在故障段上，重启前要人工清料。**下游应继续跑完清料时间**。
- **清料时间靠猜** → 短了没清完就停，长了空转浪费。**用「带长÷带速」算，实测带速**。
- **只用延时不用零速/打滑检测** → 带断了、打滑了、电机转但带不走，程序完全不知道，上游继续送料 → 堆料。**关键输送线必须有零速或测速检测**。
- **拉绳开关按 NO 接线** → 断线时拉绳失效且看不出来。**拉绳、跑偏、堵料开关一律 NC 接线**。
- **拉绳开关只进 PLC，不进硬线停机回路** → 拉绳是人身安全装置（有人被带卷住时唯一的求救手段）。**标准 PLC 的程序逻辑不能作为安全功能** —— 标准 CPU + 标准 I/O 单通道无冗余无诊断，对应 ISO 13849-1 **Category B，上限 PL b**。
  → 【惯例，本项目强制】拉绳开关必须同时接入**硬线停机回路**，程序里的读取只用于状态显示、报警和联锁。
- **双线圈**：每段的运行输出在启动、停止、故障三处各写 → 混用 `Coil` 与 `RCoil` 时 `Coil` 每周期无条件赋值会冲掉复位。**统一为一种写法**，F11 必查。
- 🔴 **运行中改清料时间 PT 无效**（官方 Table 7-19）→ 先复位定时器。
- **段数增加时逻辑复制粘贴改漏** → 段数 ≥ 4 时**改用循环/数组 + 索引**（SCL 更合适），或至少建立严格的命名规则并逐段核对。
- **重启前不检查"带上有料"** → 带上满料时直接启动，启动转矩不够 / 电机过载。**重载重启需人工确认或先反转卸料**。

### 上机前必须确认　⚠️【待老殷审】

- [ ] **启动顺序 = 从末段到首段**（现场逐段实测启动顺序，看着带子一段段启）
- [ ] **停止顺序 = 从首段到末段**，且各段清料时间够（实测：满料时停机，确认带上料被送空）
- [ ] 某段故障时**上游立即停、下游继续清料**（实测：人为触发中间段故障，观察行为）
- [ ] 清料时间由「实测带速 + 带长」算出，不是估的
- [ ] 拉绳 / 跑偏 / 堵料 / 零速开关**全部 NC 接线**，万用表逐个验证
- [ ] **拉绳开关已接入硬线停机回路**，不只进 PLC　【惯例，本项目强制】
- [ ] 零速 / 打滑检测已接入，且超时报警时间已实测
- [ ] 各段热保护 / 变频故障已接入且 NC
- [ ] 满料重启的处理方式已与甲方确认（人工确认 / 反转卸料 / 直接启）
- [ ] 交叉引用 F11 确认每段输出只有一处写入方式（不混用 Coil 与 SCoil/RCoil）
- [ ] 输送线沿线的**人身防护与防护罩**由机械/安全专业设计　【分工声明】
