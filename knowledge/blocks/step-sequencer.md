## 3.1　步序状态机

**id** `step-sequencer`

### 名称/别名
**中文**：步序状态机 · 状态机 · 工步 · 节拍 · 流程控制 · 步进控制
**英文**：Step Sequencer · State Machine · Sequence Control · Step Chain

### 适用场景
任何"按固定顺序做一串动作"的设备：转盘分度 → 气缸下压 → 保压 → 抬起 → 再分度。**这是自动化程序的骨架，写好了整个程序清晰，写坏了整个程序无法维护。**

### 梯形图逻辑描述

**核心原则（总表原文）：用 Int 变量表示步号 + 步进条件驱动，不要用一堆自锁位互相打结。**

推荐步号规划（**留间隔便于插步**）：

```
0   待机（急停/报警后必须回这里）
10  就绪 / 等料
20  动作 1
30  稳定 / 延时
40  动作 2
50  保压 / 等待
60  复位 / 回位
→ 回 10 循环
```

**每步三件事：进入条件、执行内容、退出条件（含超时）。**

```
Network 1: 步 10 —— 执行内容
  Eq([步号], 10)  →  线圈[等料指示]
  Eq([步号], 10) 串联 常开[允许运行]  →  线圈[进料输出]

Network 2: 步 10 —— 退出条件
  Eq([步号], 10)
      串联 常开[步内已驻留]           ← 关键！见下文「LAD 特有陷阱」
      串联 常开[料到位]
      →  Move(20) → [步号]
      →  RCoil[步内已驻留]

Network 3: 每次步号变化后置"已驻留"（下一扫描才为真）
  常开[步号变化] → PBox → RCoil[步内已驻留]
  常闭[步号变化] → SCoil[步内已驻留]

Network 4: 步 20 —— 执行 + 退出（同构）
  Eq([步号], 20) → 线圈[气缸下压请求]
  Eq([步号], 20) 串联 常开[步内已驻留] 串联 常开[下压到位]
      → Move(30) → [步号]

…

Network N: 急停 / 报警 → 强制回零
  常开[有报警] 并联 常开[急停辅助触点动作] 并联 常闭[方式=自动]
      →  Move(0) → [步号]
      →  RCoil[全部动作请求]
```

`Eq` / `Ne` / `Move` **全部已实证**。

### 🔴 LAD 特有陷阱：一个扫描周期连跳多步

**这是本积木最重要的一条，来自《整定值》2.5 的官方文档核实：**

- **SCL**：官方文档明确 `CASE` 执行完即结束、`FOR` 是纯计数循环且**循环变量不可在循环内改变**。所以**想用循环包住 CASE 在一个扫描周期内连推多步，在 SCL 里做不到** —— 这反而**免费保证了「每步至少驻留一个扫描周期」**。
- **LAD**（`Eq` 比较 + `Move` 写步号）：**没有这个保障**。如果第 N 步的退出条件在写入步号后的**同一次扫描**里就成立，可能一个周期连跳几步，**中间步的动作根本没执行**。

**→ LAD 实现必须手工加「进入标志」位**：进入某步时置位，该位为真时才允许判退出条件，且判过一次就复位。这就是上面 Network 2/3 里 `步内已驻留` 的作用。

**这条坑的表现极难查**：程序看起来完全正确，在线监视步号跳得太快看不出来，现场表现是"某个气缸偶尔不动"。

### 📌 SCL 实现（S7-1200/1500 更推荐）

用 `CASE #Step OF`。**注意：SCL 的 CASE 分支不使用 `BEGIN...END`**（本机 `botu-programming` 技能库明确指出这一点）。

相关报错【本机】：
EN: `Invalid data type for CASE expression.` / ZH: `表达式的数据类型无效。`
→ CASE 表达式必须是整型（Int/DInt/SInt 等），不能用 Real 或 Bool。

### 📌 若用 S7-GRAPH（仅 S7-1500，S7-1200 不支持）

步超时是**语言内置属性** —— `Step` 元素上直接有 `MaximumStepTime` 和 `WarningTime` 两个属性，**不用手写定时器**。
⚠️ 注意这两个属性的 **XSD 类型是 `xs:string`**，要填 S7 时间字面量（`T#10s`）而不是数字（《整定值》2.5）。
⚠️ **GRAPH 是否需单独 license 未取证**（《总索引》第七节）；**S7-1200 不支持 GRAPH 已四方交叉证实**。

### 变量表

| 名称建议 | 数据类型 | 方向/存储区 | 说明 |
|---|---|---|---|
| `步号` / `Step` | **Int** | **DB**（非保持，或首次扫描清零） | **只允许在一处赋值** |
| `步号_上周期` / `Step_Last` | Int | DB | 变化检测 |
| `步内已驻留` / `Step_Settled` | Bool | M / DB | **LAD 必需**，防一周期连跳 |
| `步进入沿` / `Step_Chg_P` | Bool | **Static**（FB）/ M（FC） | 边沿 M_BIT，独占 |
| `允许运行` / `En_Auto` | Bool | M | 方式 + 安全 + 无报警 |
| `有报警` / `Alm_Any` | Bool | M / DB | 见 4.1 |
| `循环计数` / `Cycle_Cnt` | DInt | 保持性 DB | 产量（见 3.4，🔴 计数器） |
| 各步动作请求 | Bool | M | 由步号派生，供设备积木使用 |

**为什么步号用 Int 而非 Byte**：留扩展空间（总表原文）。

### 参数与整定

| 参数 | 建议初值 | 范围 | 依据 |
|---|---|---|---|
| **单步超时** | 该步正常动作时间 × **2** | 该步正常时间 × **1.5–3** | **每一步都必须有**。短了误报警（现场会把报警关掉，**比没有更糟**）；长了卡步半天没人知道（《整定值》2.5） |
| 整个循环超时 | Σ 各步正常时间 × **1.5** | — | 兜底，防某步反复重入（《整定值》2.5） |
| **步进最小驻留时间** | **≥ 1 个扫描周期** | — | 见上文 LAD 陷阱（《整定值》2.5） |
| 各步"正常动作时间" | **必须现场实测记录** | — | 正常运行时记录各步实际用时（《整定值》第四节整定值表要求） |

**不许拍脑袋填占位值就交货**（总表原文：「每一步的超时时间已按实际动作时间整定（不是拍脑袋的占位值）」）。

### 常见坑　⚠️【待老殷审】

- 🔴 **一个扫描周期连跳多步** —— 见上，LAD 必须加「进入标志」位。这是本积木的头号坑。
- 🔴 **急停/报警时状态机不回零** → 报警清除后从中间某步继续跑，动作序列错乱，可能撞机。**必须回零**（总表原文）。
- 🔴 **回零后自动重启** → 绝不允许。**回零后必须人工复位才能再启动**（总表原文）。这一点与 ISO 13850:2015 **4.1.4** 同精神：「The disengagement of the device shall not restart the machinery but only permit restarting.」（该条款针对急停器件，是【标准强制】；状态机回零后不自启在本项目按【惯例，本项目强制】执行）。
- **某步没有超时监控** → 卡步了**无声无息等一辈子**（总表原文）。**每步都要有。**
- **步号写死在多处赋值** → 失同步（总表原文）。**步号只在一个地方赋值**，其他地方只读。F11 必查。
- **步号用 Byte** → 扩展时不够用，且与 Int 比较时类型不匹配。
- **步号放保持性存储区** → 断电重启从中间步继续，且没人知道。**不放保持区，或首次扫描强制 0**。
- **复位按钮在运行中误触发** → 必须带方式判断（总表原文：「复位按钮不会在运行中误触发（需带方式判断）」）。
- **步号规划不留间隔**（0,1,2,3…）→ 中间要插一步就得把后面全改一遍，改漏就出事。**用 10 的倍数**。
- **动作请求直接写 Q，不经中间位** → 同一个 Q 在多个步里被写 = 双线圈。**每步只置"请求位"，输出统一在一处汇总**。
- **`Move` 的类型不匹配**【本机】：
  EN: `Data type '{1}' cannot be converted implicitly into data type '{2}'.`
  ZH: `变量 {1} 的初始化与所声明的数据类型不匹配。`
  🔑 **先查块的 IEC check 属性**。
- **步号变量未声明**【本机】：
  EN: `Tag {1} not defined.`（LAD/FBD 侧）
  EN: `Tag '{1}' is not declared.` / ZH: `变量 {1} 未声明。`（SCL 侧）
  ⚠️ **注意措辞**：常见写法 `Tag "..." is not defined` **不准确**。真实模板是这两条，做正则匹配要两条都覆盖。
  SCL 里漏 `#` 前缀走的就是 SCL 那条（漏 `#` 时标识符被当作全局 PLC 变量解析，变量表里没有 → 报"未声明"）。
  > ⚠️ **诚实标注**：字符串是真机原文，但"漏 `#` 必然触发这一条"是**机理推断，未在真机造错验证**。

### 上机前必须确认　⚠️【待老殷审】

- [ ] **每一步的超时时间已按实际动作时间整定**（现场记录各步实际用时，不是拍脑袋的占位值）
- [ ] **急停后状态机确实回零**（仿真 + 实机验证）
- [ ] **回零后不自动重启**，需人工复位（实机验证：报警 → 复位 → 确认不自跑，需再按启动）
- [ ] **复位按钮不会在运行中误触发**（已带方式判断，实机在自动运行中按复位验证）
- [ ] LAD 实现已加**「进入标志」位**，且实测过「一个扫描周期不会连跳两步」（可用步号变化计数或在线跟踪验证）
- [ ] 步号**只有一处赋值**（交叉引用 F11 确认）
- [ ] 步号**不在保持区**，或首次扫描强制 0（断电重启不从中间步继续）
- [ ] 每步的动作请求**不直接写 Q**，输出在一处汇总（无双线圈）
- [ ] 步号规划留了间隔，插步不需要改动其他步
- [ ] 所有步的超时都会**产生报警**并停机，不是无声跳过
- [ ] 单步/整循环超时都进了交付文档整定值表，"已确认"列由现场签字

### 可生成性
**✅ 可自动生成。** `Eq`、`Ne`、`Move`、`Contact`、`Contact`+`<Negated>`、`Coil`、`SCoil`、`RCoil`、`PBox`、`O` 全在白名单且有实证。
⚠️ 生成时**必须自动带上「进入标志」位**，不能省 —— 省了程序看起来对但会偶发丢步。
