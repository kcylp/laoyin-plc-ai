## 2.7　PID 温控

**id** `pid-temp`

### 名称/别名
**中文**：PID 温控 · 恒温控制 · 闭环温度控制 · PID 调节 · PID_Compact
**英文**：PID Temperature Control · Closed-loop Temperature Control · PID_Compact / PID_Temp

### 适用场景
加热棒/加热带/加热圈的闭环温度控制，或任何需要闭环调节的模拟量回路（压力、流量、张力）。

### 🔴 为什么暂不可自动生成

`PID_Compact`（通用 PID）与 `PID_Temp`（专为温度设计，带加热/制冷双输出与自整定）**都是带背景 DB 的 FB 调用**。而《技术底座》第三节确认：

> `<Call>` 调用 FB/FC —— **全项目零实例、零验证**。这意味着当前**根本生成不出「在梯形图里调用另一个块」的 XML**。

**必须先做 TASK-012A。** 在那之前，不许猜着生成 `<Call>` —— 那会导致导入失败或**更糟的静默错误**。

### 梯形图逻辑描述（模式 + 手工添加指引）

**PLC 侧梯形图能做的部分（这部分 ✅ 可生成）**

```
Network 1: 温度标定（见 2.6）
  Convert / Sub / Div / Mul / Add  →  [温度工程值 : Real]

Network 2: 传感器故障与超温联锁（安全相关，必须有）
  Lt([温度原始值], [断线阈值])  →  SCoil[热电偶断线]
  Gt([温度工程值], [超温联锁值]) →  SCoil[超温报警]
  常开[热电偶断线] 并联 常开[超温报警]  →  RCoil[允许加热]

Network 3: PID 使能条件汇总
  常开[自动方式] 串联 常闭[有报警] 串联 常开[温度信号正常]
      →  线圈[允许加热]

Network 4: 【🔴 手工添加】调用 PID_Temp / PID_Compact
  —— 当前无已验证 XML 写法，必须在博途里手工插入并组态

Network 5: PID 输出到执行机构
  （若为固态继电器 PWM 输出：PID 的 OutputPWM 直接接 Q）
  常开[PID.OutputPWM] 串联 常开[允许加热]  →  线圈[加热输出]
```

**手工添加指引（用户在博途里做的部分）**

1. 在 **OB（循环中断 OB，如 OB30/OB200）** 里插入 PID 指令 —— **PID 必须在恒定周期的循环中断 OB 里调用**，不能放主循环 OB1（采样周期不恒定，积分/微分算不对）。
2. 指令选择：**纯温度用 `PID_Temp`**（有加热/制冷双输出、有整定），通用回路用 `PID_Compact`。
3. 插入时会提示创建**背景 DB**，接受即可。
4. 组态：工艺对象视图里设 **输入类型**（Real / 模拟量原始值 / 温度）、**输出类型**（模拟量 / PWM / 步进）、**过程值上下限**、**输出限值**。
5. 参数整定：**先用「预调节」（Pretuning）自整定**，再用「精确调节」（Fine tuning）。
6. 采样时间在**工艺对象里设**，且**必须与循环中断 OB 的周期一致**。

### 参数与整定

| 参数 | 建议做法 | 依据 |
|---|---|---|
| **Kp / Ti / Td** | ❌ **不给数值** —— **用博途的自整定（预调节 + 精确调节）** | PID 参数完全取决于对象的时间常数、纯滞后、增益，无通用值。**给数字是不负责任的** |
| **采样时间** | 与循环中断 OB 周期一致 | 数学要求。温度对象慢，常见 100 ms ~ 1 s |
| **PWM 周期**（若 SSR 输出） | **视执行器定** —— SSR 可短（1–2 s），机械接触器必须长（≥ 20–60 s） | 机械接触器寿命有限（百万次量级），PWM 周期短会几天内打坏 |
| **超温联锁值** | 设定值 + 工艺允许偏差；**必须问甲方** | 与被加热物料、设备耐温相关，工艺参数 |
| 温度信号滤波 | 视噪声定 | 热电偶信号弱，易受干扰 |
| 升温速率限制 | 视工艺定 | 玻璃/陶瓷/塑料有热应力限制 |

### 常见坑　⚠️【待老殷审】

- **PID 放在 OB1（主循环）** → 采样周期随程序负载变化，积分和微分算出来的东西没有意义，表现为"整定好了过几天又不稳"。**必须放循环中断 OB，且采样时间与 OB 周期一致。**
- **不做超温独立联锁** → PID 输出饱和、SSR 短路、热电偶脱落时**持续满功率加热**。
  🔴 **这是会起火的失效模式。**
  → 【惯例，本项目强制】必须有**独立于 PLC 的硬件超温保护**（机械式温控器 / 独立超温继电器，直接切断加热回路）。理由与急停同：标准 CPU + 标准 I/O ≈ ISO 13849-1 **Category B，上限 PL b**，程序不能是"移除危险能量"链上的必要环节。
- **热电偶断线不检测** → 热电偶断线时很多模块读数是**上溢（超量程高）或下溢（超量程低）**。若读成低温，PID 会**持续满功率加热**。**必须做断线/超量程检测并联锁停止加热。**
- **热电偶极性接反** → 温度反向变化，PID 正反馈，加热越加越"冷"，直到烧毁。**必须现场加热验证读数上升。**
- **PID 作用方向（正/反作用）设错** → 同上，正反馈。加热是"过程值低于设定 → 输出增大"，制冷相反。
- **PWM 周期太短驱动机械接触器** → 接触器几天内打坏。**SSR 才能用短周期**。
- **手动/自动切换不做无扰动切换** → 切到自动瞬间输出跳变，温度冲过头。PID 指令本身有无扰动切换支持，但**必须正确接线/组态**。
- **自整定在带载状态之外做** → 空载整定的参数带载后不适用。**整定必须在实际工况下做**。
- **背景 DB 相关报错**【本机】：
  EN: `Instance data block does not match called FB.` / ZH: `背景数据块与被调用 FB 不匹配。`
  EN: `Time stamp conflict of the instance data block.` / ZH: `背景数据块时间戳冲突。`
  ZH: `背景数据块缺失。`
  EN: `The data type {1} of the actual parameter does not match the data type {2} of the formal parameter.` / ZH: `实参的数据类型 {1} 与形参的数据类型 {2} 不匹配。`
  ⚠️ **注意**：社区流传的 `The instance ... is not defined` 与 `A block instance must be assigned` **已判定为伪造**（查无官方出处），不要采信。
- **「更新块调用」的行为细节**（官方，用户最容易困惑）：新增参数会被加入但 **FB 的新参数默认隐藏**（需右键"显示所有参数"）；**已删除的参数不会自动移除，必须手工删**；重命名参数会自动改名；官方 Note：若更新会导致参数供值出错，则**不能**使用"更新块调用"。
- **PID 指令不被该 CPU 支持**【本机】：
  EN: `{0} NW {1}: The instruction {2} is not supported by the new CPU.`
  ZH: `程序段不支持该指令。`
  ⚠️ 区分：搜索里常见的 "CPU not supported" 多指**在线连接时固件版本不匹配**，与编译期指令不支持是两回事。

### 上机前必须确认　⚠️【待老殷审】

- [ ] PID 在**循环中断 OB** 里调用，采样时间与 OB 周期一致
- [ ] **独立于 PLC 的硬件超温保护已安装并实测**（机械温控器 / 超温继电器直接切加热回路）　【惯例，本项目强制】
- [ ] 热电偶/热电阻**断线与超量程检测已实现并实测**（拔线，确认停加热 + 报警）
- [ ] 热电偶**极性正确**（现场加热，确认读数上升）
- [ ] PID **作用方向**正确（加热 = 反作用/正作用，按指令定义核对；实测：设定值抬高 → 输出增大）
- [ ] PWM 周期与执行器类型匹配（**机械接触器绝不用短周期**）
- [ ] 自整定在**实际带载工况**下完成，参数已记录进交付文档
- [ ] 超温联锁值由**甲方书面提供**
- [ ] 手自动切换无扰动（实测切换，观察输出不跳变）
- [ ] 加热区的**防火、隔热、烫伤防护**由工艺/安全专业负责　【分工声明】
- [ ] 升温速率限制（若工艺有要求）已实现
