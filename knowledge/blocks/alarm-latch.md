## 4.1　报警锁存与汇总

**id** `alarm-latch`

### 名称/别名
**中文**：报警锁存 · 报警汇总 · 故障锁存 · 报警复位 · 报警字
**英文**：Alarm Latching · Alarm Summary · Fault Latch & Reset · Alarm Word

### 适用场景
每个工程都要有。把分散的故障信号锁存、汇总成一个"有报警"位用于停机联锁和指示灯，并提供人工复位。

### 报警处理的三条原则（总表原文，本文补依据与实现）

**1. 锁存**：报警发生即锁存，**不因条件消失而自动清除** —— 否则**瞬时故障会被漏掉**。
**2. 汇总**：所有报警 OR 成一个「有报警」位，用于停机联锁和指示灯。
**3. 人工复位**：复位必须人工按，且**复位条件里要串「故障已消失」** —— 否则按了没用还以为坏了。

### 梯形图逻辑描述

```
Network 1..n: 各路报警锁存（每路一个 SCoil）
  常开[热保护跳闸]        →  SCoil[Alm_OL]
  常开[变频器故障]        →  SCoil[Alm_VFD]
  常开[步超时]            →  SCoil[Alm_StepTmo]
  常开[气缸到位超时]      →  SCoil[Alm_CylTmo]
  常开[传感器故障]        →  SCoil[Alm_Sensor]
  常开[急停辅助触点动作]  →  SCoil[Alm_EStop]        ← 仅状态记录，见 4.2
  …

Network n+1: 汇总（O 块，Card = 报警路数）
  常开[Alm_OL] 并联 常开[Alm_VFD] 并联 常开[Alm_StepTmo] 并联 …
      →  线圈[有报警]

Network n+2: 停机联锁
  常开[有报警]  →  RCoil[允许运行]，Move(0) → [步号]

Network n+3: 指示与声光
  常开[有报警] 串联 常开[闪烁位]  →  线圈[报警灯]      （见 1.7）
  常开[有报警] 串联 常闭[已消音]  →  线圈[蜂鸣器]

Network n+4: ⚠️ 复位 —— 必须串「故障已消失」
  常开[复位按钮] → PBox
      串联 常闭[热保护跳闸]       ← 现行故障条件必须已消失
      →  RCoil[Alm_OL]
  常开[复位按钮] → PBox 串联 常闭[变频器故障]  →  RCoil[Alm_VFD]
  …
  （或：常开[复位沿] 串联 常闭[任一现行故障] → 一次性复位全部）

Network n+5: 消音（独立于复位）
  常开[消音按钮] → PBox  →  SCoil[已消音]
  常开[有报警变化] → PBox →  RCoil[已消音]        ← 新报警来了要重新响
```

**为什么复位要逐路串对应的"现行条件"**：若统一用「任一现行故障消失才允许复位」，则一个未修好的故障会**挡住其他已修好故障的复位**，现场会很烦。**逐路复位更好**，但 network 数量多；若路数很多，折中做法是分组。

### 变量表

| 名称建议 | 数据类型 | 方向/存储区 | 说明 |
|---|---|---|---|
| `Alm_xxx`（每路一个） | Bool | **DB**（建议集中在一个报警 DB） | 锁存位 |
| `报警字` / `Alm_Word` | Word / DWord | DB | 打包给 HMI/上位机用（可选） |
| `有报警` / `Alm_Any` | Bool | M / DB | 汇总位 |
| `允许运行` / `En_Run` | Bool | M | 被报警复位 |
| `复位按钮` / `PB_Reset` | Bool | I | |

| `消音按钮` / `PB_Mute` | Bool | I | |
| `已消音` / `Muted` | Bool | M | |
| `报警灯` / `Lamp_Alm` | Bool | Q | |

**建议把所有报警锁存位集中在一个 DB 里、连续排布** —— 便于打包成字给 HMI、便于做汇总、便于交叉引用核查。

### 参数与整定

| 参数 | 建议初值 | 依据 |
|---|---|---|
| 报警灯闪烁 | 亮 0.5 s / 灭 0.5 s（一般）；亮 0.2 s / 灭 0.2 s（紧急） | 人眼可辨识闪烁频率 1–3 Hz；快闪表示更紧急是行业惯例（《整定值》2.6） |
| 报警确认后抑制期 | **1–3 s** | 防同一故障反复刷屏（《整定值》2.6） |
| 报警延时（防瞬时波动误报） | 3–10 s（模拟量类）；0（开关类瞬时故障必须立即锁存） | 与信号性质相关 |
| 通信超时（若有通信报警） | 请求周期 × 3，且 ≥ 500 ms | 留网络抖动（《整定值》2.6） |

⚠️ **注意矛盾点**：报警延时是为了防误报，但**瞬时故障恰恰是锁存要抓的对象**。
**处理原则**：模拟量越限类可加延时；**开关类瞬时故障（急停、热保护跳闸、安全门开）必须零延时立即锁存**。这两类要分开处理，不能一刀切。

### 常见坑　⚠️【待老殷审】

- 🔴 **不锁存，用 `Coil` 直接跟随故障条件** → **瞬时故障被漏掉**。表现为"设备偶尔停一下又好了，什么都没记录"。这是本积木存在的全部理由。
- 🔴 **复位不串「故障已消失」** → 故障还在就把锁存清了，`Coil` 下一周期又置上，现场表现是"**按复位没用**"，操作工会以为按钮坏了或程序坏了。
  → 必须串现行条件的常闭。
- 🔴 **复位不用边沿** → 按住复位键期间报警一直被清，松手又全回来。
- **报警锁存位放在保持性存储区** → 断电重启后所有历史报警都还在，操作工要复位一大堆。**通常不放保持区**（但若甲方要求断电也不丢报警，则放保持区并在交付文档说明）。
- **`Coil` 与 `SCoil`/`RCoil` 混用同一个报警位** → `Coil` 每周期无条件赋值，把锁存冲掉。**同一位只能用一种写法**。F11 必查。
- **汇总用了 16 路以上的 O 块 / 一个 network 堆太多线圈**【本机 `BL_TOO_MANY_COILS`】：
  EN: `Too many coils in one network. A maximum of 16 parallel coils is allowed.` / ZH: `一个程序段中的线圈太多。最多允许有 16 个并联线圈。`
  → **拆 network 分级汇总**（先分组汇总，再总汇总）。
- **`O` 块的 `Card` 与实际支路数不一致** → 导入或编译异常。`Card` = 并联支路数，支路接 `in1`/`in2`/…/`inN`（《技术底座》2.3）。
- **消音与复位混为一个按钮** → 消音后报警也被清了，隐患被掩盖。**消音与复位必须是两个独立动作**。
- **消音后新报警不重新响** → 操作工按了消音去干别的，新故障来了没人知道。**新报警到来时必须解除消音**。
- **报警只有"有报警"一个位，没有分路** → 操作工只知道"有故障"，不知道是哪个。**必须分路 + HMI 显示明细**。
- **报警文本写在 PLC 里** → 改文本要重新下装 PLC。**报警文本放 HMI**，PLC 只出位。
- **急停辅助触点被当成安全功能** → 见 4.2。程序里读急停**只能**用于状态显示、报警锁存、状态机回零。
- **报警不联锁停机** → 只亮灯不停机，故障状态下继续生产出废品或撞机。**除工艺明确允许的"警告级"报警外，故障必须联锁停机**。
  → 建议分级：**警告（不停机，只提示）/ 故障（停机，可复位）/ 严重（停机，需检查后专人复位）**。分级方案需与甲方确认。

### 上机前必须确认　⚠️【待老殷审】

- [ ] **所有报警都是锁存的**（`SCoil`，不是 `Coil`），逐条核对
- [ ] **每路复位条件都串了「该路故障已消失」**（实测：故障未消除时按复位，报警不清）
- [ ] 复位**用边沿触发**（按住不放不会持续清报警）
- [ ] **消音与复位是两个独立按钮/动作**，且新报警到来时自动解除消音（实测）
- [ ] 报警**分路**，HMI 能显示到具体哪一条（不是只有"有故障"）
- [ ] 报警**联锁停机**（分级方案已与甲方确认，哪些停哪些不停有书面记录）
- [ ] 报警锁存位的保持性策略已确认（通常不保持；若甲方要求保持，已在交付文档说明）
- [ ] 同一报警位**只用一种写法**（全 SCoil/RCoil，不混 Coil），F11 查过
- [ ] 分级汇总已拆 network，未撞 16 线圈上限
- [ ] 报警文本在 HMI，改文本不需重新下装 PLC
- [ ] **瞬时故障（急停、热保护跳闸、安全门）零延时锁存**，已实测（快速拍一下急停再松开，确认报警被抓到）
- [ ] 报警灯/蜂鸣器有断线或周期自检（关键指示）
