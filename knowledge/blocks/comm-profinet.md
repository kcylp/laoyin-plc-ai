## 6.3　Profinet IO 读写

**id** `comm-profinet`

### 名称/别名
**中文**：Profinet IO 读写 · 分布式 IO · ET200 远程站 · IO 直接访问 · 周期性过程数据
**英文**：Profinet IO Access · Distributed I/O · Cyclic Process Data

### 适用场景
读写 Profinet 网络上的分布式 IO（ET200SP/ET200MP/ET200eco）、支持 Profinet 的变频器（G120 的标准报文）、智能传感器。

**✅ 关键优势：Profinet IO 的周期性过程数据是通过「直接地址访问」实现的 —— 就是普通的 `I` / `Q` 地址，不需要任何通信块调用。** 这也是本类唯一可生成的一条（总表：「✅ 直接地址访问部分可生成」）。

### 梯形图逻辑描述

**A. 周期性过程数据（✅ 完全可生成 —— 就是普通 I/Q 访问）**

组态好 Profinet 设备后，博途自动分配 I/Q 地址，程序里当本地 IO 用：

```
Network 1: 读远程站的输入（与本地 IO 写法完全相同）
  常开[远程站_启动按钮]  →  …            ← 这就是一个普通的 I 点

Network 2: 写远程站的输出
  常开[电机运行]  →  线圈[远程站_接触器]  ← 这就是一个普通的 Q 点

Network 3: 变频器控制字/状态字（G120 标准报文 1 等）
  Move([控制字], [变频器_控制字])          ← QW 地址
  Move([变频器_状态字], [状态字])          ← IW 地址
  Move([速度设定], [变频器_速度设定])      ← QW
  Move([变频器_实际速度], [实际速度])      ← IW
```

**B. 站点诊断与故障处理（✅ 可生成的部分 + 🔴 需块调用的部分）**

```
Network 4: ✅ 站点故障的间接判定（可生成）—— 用"数据是否在变化"或看门狗
  Ne([远程站_心跳], [心跳_上次])  → PBox → RCoil[心跳超时定时器IN]
  Move([远程站_心跳]) → [心跳_上次]
  常闭[心跳变化] → T_HbTmo(IN)，PT = 心跳超时
  常开[T_HbTmo.Q] → SCoil[Alm_StationLost]，RCoil[远程站数据可信]

Network 5: 🔴 站点诊断的正规做法需要系统块（DeviceStates / GET_DIAG / LED 等）
  —— 这些是块调用，当前无已验证 XML 写法
```

**C. 非周期性数据（参数读写）—— 🔴 需块调用**
`RDREC` / `WRREC`（读写数据记录）、`RD_ADDR` 等系统块 → **块调用，🔴**。

### 🔑 一个必须讲清的事实

**Profinet 站点掉线时，其输入区的行为取决于组态，不是"保持最后值"那么简单。**
- 站点故障时输入通常被置为 **0**（替代值行为可组态）
- **但"输入为 0"与"真实信号为 0"程序无法区分** —— 这正是必须做站点诊断的理由

**→ 所以即使周期性数据可生成，「站点在线判定」也必须有。** 上面 Network 4 的心跳法是**不依赖块调用的可生成方案**（用远程站上一个已知会变化的信号，或用本地 Q 输出到远程站再从远程站输入读回构成回环）。

### 变量表

| 名称建议 | 数据类型 | 方向/存储区 | 说明 |
|---|---|---|---|

| `变频器_控制字` | Word | **Q**（QW） | 报文格式见驱动手册 |
| `变频器_状态字` | Word | **I**（IW） | |
| `变频器_速度设定` | Int | Q（QW） | 通常为归一化值（4000h = 100%） |
| `变频器_实际速度` | Int | I（IW） | |

| `心跳_上次` / `Stn_HB_Last` | Word / Bool | M / DB | |

### 参数与整定

| 参数 | 建议初值 | 依据 |
|---|---|---|
| **心跳/看门狗超时** | **Profinet 更新时间 × 5**，且 ≥ 200 ms | Profinet 本身的看门狗时间通常是更新时间 × 3（组态项）。程序侧要更宽松，避免与协议层看门狗打架 |
| Profinet 更新时间 | **在网络组态里设**，视 IO 数量与实时性需求定 | 组态参数 |
| 变频器速度归一化 | **4000h = 100%**（西门子惯例，**必须查驱动手册确认**） | 驱动参数 |
| 站点掉线时的替代值 | **在设备组态里设**，视安全策略定 | ⚠️ 默认通常为 0，**必须确认 0 是安全侧** |
| 连续失败阈值 | 视工艺定 | |

### 常见坑　⚠️【待老殷审】

- 🔴 **站点掉线时"输入为 0"被当成"真实信号为 0"** → 例如"安全门关闭"信号在远程站上，站点掉线 → 信号变 0 → 程序以为门开了（这个方向恰好是安全的）；但"料位低"信号掉线变 0 → 程序以为料位不低 → **继续生产** —— **方向就错了**。
  **→ 每个来自远程站的信号都要问一句：站点掉线时这个信号变 0，是导向安全侧还是危险侧？** 导向危险侧的必须靠站点诊断兜住。
- 🔴 **没有站点在线判定** → 见上。**必须有。**
- 🔴 **替代值组态默认为 0 但 0 不是安全侧** → 必须逐点确认。这是 Profinet 分布式 IO 最容易出事故的地方。
- **变频器报文格式没查手册** → 控制字位定义、速度归一化基数（4000h=100%）、状态字位定义各家不同。**必须查驱动手册。**
- **变频器速度设定用工程量直接写** → 需归一化。写 1500（想表示 1500 rpm）实际是 1500/16384 ≈ 9.2%。
- **心跳法用了一个"不一定会变"的信号** → 设备正常但信号恰好不变时误报站点掉线。**要用回环（本地 Q → 远程站 → 远程输入 → 读回）或确知会周期变化的信号。**
- **优化访问的 DB 与 IO 区混淆** → I/Q 区本身是绝对寻址，不受优化访问限制；但把 IO 数据搬进优化 DB 后再用绝对地址就会报【本机】：
  EN: `Absolute access to data in blocks with optimized access is not permitted.` / ZH: `不允许在具有优化访问的块中对数据进行绝对寻址。`
- **访问类型不被 CPU 支持**【本机】：
  EN: `This type of access is not supported by this CPU.` / ZH: `该 CPU 不支持此访问类型。`
- **安全 IO（F-IO）当普通 IO 用** → **绝对不允许。** 西门子官方《Programming Guideline Safety》§3.7.5 WARNING 原文：
  > "…**only fail-safe data or fail-safe signals of F-I/O and of other safety programs (in other F-CPUs) are permitted to be processed in the safety program.**"

  → **F-IO 的信号只能在安全程序里处理**；标准程序读 F-IO 的状态只能用于显示与联锁，**不能承担安全功能**（与 4.2 同一原则）。
- **Profinet 网络拓扑问题** → 环网/星形/线形的故障影响范围不同；交换机非工业级导致抖动。**这是硬件/网络设计问题，程序查不出来。**
- **IO 地址被博途重新分配后程序没同步** → 增删设备可能导致地址变化。**用符号名，不用绝对地址**；变更后必须重新核对。
- **不做长时间稳定性测试** → Profinet 的间歇性丢包在短时间测试中看不出来。

### 上机前必须确认　⚠️【待老殷审】

- [ ] **逐点确认**：每个来自远程站的信号，**站点掉线时变 0 是导向安全侧还是危险侧**；导向危险侧的已被站点诊断兜住
- [ ] **站点在线判定已实现**（心跳/回环法或系统块），并**实测**（拔远程站网线，确认报警 + 数据标为不可信 + 联锁动作）
- [ ] 站点掉线时的**替代值组态已逐点确认**（默认 0 不一定是安全侧）
- [ ] 变频器**报文格式已查驱动手册**：控制字位定义、状态字位定义、**速度归一化基数**
- [ ] 变频器速度设定已实测（给一个已知值，核对实际转速）
- [ ] 心跳信号是**确知会周期变化**的（或用回环），不会误报
- [ ] IO 用**符号名**访问，增删设备后已重新核对地址分配
- [ ] **F-IO（若有）未被标准程序当安全功能用**　【标准依据：Programming Guideline Safety §3.7.5】
- [ ] Profinet 更新时间与看门狗时间已按 IO 数量与实时性需求组态
- [ ] 网络拓扑与交换机等级已确认（工业级、拓扑与冗余需求匹配）
- [ ] **长时间稳定性测试已做（≥ 24 h）**，记录丢包/站点掉线次数
- [ ] 安全功能不依赖 Profinet 通信（除非是 PROFIsafe + F-CPU，且由资质人员设计）　【惯例，本项目强制】

### 可生成性
**✅ 直接地址访问部分可自动生成**（照总表标记）。
周期性过程数据的读写就是普通 `I` / `Q` 访问 —— `Contact`、`Coil`、`Move`、比较器、算术全在白名单，**与本地 IO 无差别**。
✅ **心跳/看门狗式站点在线判定也可生成**（`Ne`/`PBox`/`TON`/`SCoil`/`Move` 全在白名单）—— **这一条价值很高，因为它是"不依赖块调用"的站点诊断方案。**
🔴 **不可生成的部分**：站点诊断的正规做法（`DeviceStates` / `GET_DIAG` / `LED` 等系统块）、非周期性参数读写（`RDREC` / `WRREC`）—— 均为块调用，零实例。
