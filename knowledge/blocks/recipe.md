## 3.3　配方管理

**id** `recipe`

### 名称/别名
**中文**：配方管理 · 参数组 · 品种切换 · 工艺参数组 · 型号切换
**英文**：Recipe Management · Parameter Set · Product Changeover · Formula Handling

### 适用场景
同一台设备生产多个品种/型号，每个品种有一套工艺参数（速度、时间、温度、位置、数量）。切品种时一次性把整组参数装载到"当前参数"区。

### 梯形图逻辑描述

**核心结构：配方存储区（数组）+ 当前参数区 + 装载动作**

```
DB 结构设计（这是本积木的重点，不是梯形图）
  DbRecipe.Store : ARRAY[1..20] OF typeRecipe    ← 配方库（保持性）
  DbRecipe.Cur   : typeRecipe                    ← 当前生效参数
  DbRecipe.Sel   : Int                           ← 选中的配方号
  DbRecipe.Loaded: Int                           ← 已装载的配方号（用于校验）

  typeRecipe（PLC 数据类型 UDT）：
    Name        : String[20]
    IdxSpeed    : Real
    PressTime   : Time
    TempSP      : Real
    Qty         : DInt
    …
```

```
Network 1: 装载许可（只允许在停机/待机时切配方）
  Eq([步号], 0) 串联 常闭[设备运行] 串联 常开[手动允许]
      →  线圈[允许装配方]

Network 2: 配方号合法性检查
  Ge([配方号], 1) 串联 Le([配方号], 20)  →  线圈[配方号合法]
  常闭[配方号合法]  →  SCoil[配方号越界报警]

Network 3: 装载（边沿触发一次）
  常开[装载按钮] → PBox
      串联 常开[允许装配方] 串联 常开[配方号合法]
      →  【结构化拷贝：Store[Sel] → Cur】
      →  Move([配方号]) → [已装载配方号]

Network 4: 校验（防"以为装了其实没装"）
  Ne([已装载配方号], [配方号])  →  线圈[配方未同步提示]
```

### ⚠️ 为什么是 ⚠️（部分可生成）

**结构化拷贝（`Store[Sel]` 整个 UDT → `Cur`）在 LAD 里的实现方式**：
- 逐个字段 `Move` —— **全在白名单内 ✅**，但字段多时 network 数量爆炸（20 个字段 = 20 个 Move）
- 用 `MOVE_BLK` / `Serialize` / `Deserialize` 等块传送指令 —— **不在白名单**（零实例、未验证）🔴
- 用 SCL 的 `#Cur := #Store[#Sel];` 整体赋值 —— **一行搞定**，但那是 SCL 不是 LAD

**→ 主体逻辑（许可、合法性检查、边沿触发、校验）✅ 可生成；参数拷贝部分若字段多，建议改 SCL 或告知用户手工用 `MOVE_BLK`。这就是 ⚠️ 的来源。**

**另外，数组变量索引访问（`Store[Sel]`，索引是变量）在 LAD XML 中的写法未经验证** —— 属 🔴 待 TASK-012A。生成时若必须用变量索引，应告知用户。

### 参数与整定

| 参数 | 值 | 依据 |
|---|---|---|
| 配方数量上限 | **视工艺定** —— 问甲方要生产多少品种，留 2 倍余量 | 甲方业务参数 |
| 配方内各字段的取值范围 | **视工艺定** —— 每个字段都要有上下限校验 | 工艺参数 |
| 配方字段的初值 | ❌ **不给** —— 由甲方提供每个品种的工艺参数 | 《整定值》第五节第 4 条：工艺参数一律不猜 |

**配方的内容本身全部是工艺参数，AI 一个数都不许填。** 能做的是把结构建好、校验做好、装载逻辑做对。

### 常见坑　⚠️【待老殷审】

- 🔴 **配方库不在保持性存储区** → 断电后全部配方丢失，甲方几个月积累的工艺参数一夜没了。**这是会挨骂的一条。**
  → 保持性 DB（或用 HMI/上位机做配方存储 + 下装）。
- 🔴 **运行中切换配方** → 参数在动作过程中被改，行为不可预期（比如速度突变、定时器 PT 中途变）。
  **必须只允许在停机/待机（步号 0）时切换。**
- **不校验配方号范围** → 数组越界。S7-1200/1500 上数组越界访问会**触发错误（可能进入 STOP）**。**必须做 `Ge(1)` + `Le(上限)` 检查**。
- **装载不用边沿触发** → 按住按钮时每周期都装载，看起来没事，但会**把操作员正在编辑的参数反复冲掉**。
- **不做"已装载"校验** → 操作工改了配方号但忘按装载，以为切了其实没切，**做出一批废品**。必须有 `已装载配方号 ≠ 选中配方号` 的提示，且**显著显示在 HMI 上**。
- **配方字段无上下限校验** → 手误输入 99999 的速度直接下装到运动指令，撞机。**每个字段都要有范围校验，超范围拒绝装载并报警。**
- **配方字段的类型与使用处不匹配** → 常见报错【本机】：
  EN: `The data type {1} of the actual parameter does not match the data type {2} of the formal parameter.` / ZH: `实参的数据类型 {1} 与形参的数据类型 {2} 不匹配。`
  EN: `Data type '{1}' cannot be converted implicitly into data type '{2}'.`
  🔑 **先查块的 IEC check 属性**。
- **改 UDT 结构后不更新块调用** → 【本机】
  EN: `Instance data block does not match called FB.` / ZH: `背景数据块与被调用 FB 不匹配。`
  EN: `Time stamp conflict of the instance data block.` / ZH: `背景数据块时间戳冲突。`
  ZH: `被调用块或数据层级中所用块的时间戳比调用块的时间戳更新。这样会产生接口冲突。`
  **「更新块调用」的行为细节**（官方）：新增参数会加入但 **FB 的新参数默认隐藏**（需右键"显示所有参数"）；**已删除的参数不会自动移除，必须手工删**；重命名参数自动改名；若更新会导致参数供值出错，则**不能**用"更新块调用"。
- **优化访问的 DB 用绝对地址访问**【本机】：
  EN: `Absolute access to data in blocks with optimized access is not permitted.`（`BL_PARSE_11A5`）/ ZH: `不允许在具有优化访问的块中对数据进行绝对寻址。`
  → 配方 DB 通常是优化访问，HMI/上位机连接必须用**符号名**，不能用 `%DB1.DBW0`。**这是配方类需求做上位通信时最常撞的墙。**
- **多实例部分访问**【本机】：ZH: `不支持对多实例中的单个元素进行部分访问。`
- **改配方 DB 结构后不重新下装 HMI 变量** → HMI 读到错位的数据。**结构变更必须同步 HMI。**
- **配方里放"位置"类参数但机械已改动** → 老配方的位置值对新夹具是撞机的。**机械变更后必须重新核对所有配方的位置参数。**

### 上机前必须确认　⚠️【待老殷审】

- [ ] 配方库在**保持性 DB**（**断电重启实测：配方还在**）
- [ ] **只允许在停机/待机时切换配方**（实机：运行中试切，确认被拒绝）
- [ ] 配方号**范围校验已实现**（试输入 0 和上限+1，确认拒绝且报警，**不会进 STOP**）
- [ ] 装载**用边沿触发**（按住按钮不会反复装载）
- [ ] **"已装载 ≠ 选中"的提示已实现且在 HMI 上显著显示**（这一条能防批量废品）
- [ ] 每个配方字段都有**上下限校验**，超范围拒绝装载并报警
- [ ] 位置类参数的配方值已在**当前机械状态下逐个验证**（不是沿用旧机械的值）
- [ ] 配方 DB 的访问类型（优化/标准）与 HMI/上位机连接方式匹配，用**符号名**访问
- [ ] 配方内容由**甲方书面提供**（每个品种每个字段），AI/工程师未填任何工艺数值
- [ ] 配方有**备份与恢复**手段（HMI 导出 / 上位机存档），且已实测恢复流程
- [ ] UDT 结构变更后已同步更新块调用与 HMI 变量
