## 1.1　电机起保停（自锁）

**id** `start-stop`

### 名称/别名
**中文**：电机起保停 · 起保停 · 自锁 · 启保停 · 自保持
**英文**：Start-Stop with Seal-in · Latching Circuit · Self-holding Circuit · Motor Start/Stop

### 适用场景
一个启动按钮 + 一个停止按钮控制一台电机（或任何需要"按一下就一直运行"的负载）。松手后负载保持运行，直到按停止。**这是梯形图的第一课，也是本项目现有样板写错的那一条。**

### 梯形图逻辑描述

```
(常开[启动按钮]  并联  常开[电机运行])  串联  常开[停止按钮信号]  →  线圈[电机运行]
```

ASCII：

```
Network 1: 电机起保停
    |   启动按钮      停止按钮信号                 |
    |----| |----------+---| |-------------( )-----|  电机运行
    |                 |                            |
    |   电机运行(自锁) |                            |
    |----| |----------+                            |
```

**结构要点**

1. **并联分支用 `Part Name="O"` + `Card=2` 实现**（`Card` = 并联支路数，支路接 `in1`/`in2`）。这是白名单里唯一的并联手段。
2. **自锁分支引用的是输出自己**（`电机运行`），**不是另设一个中间位**。用中间位会多一个扫描周期延迟，且在多块/多 OB 场景下容易失同步。
3. **串联不需要专门指令** —— 直接把前一个的 `out` 接后一个的 `in`。

### ⚠️ 关于本项目现有"黄金样板"的纠正

`LAD_块级导入_起保停.xml` **不是完整的起保停**。它只有 `Start AND NOT Stop → Motor`，**缺自锁并联分支** —— 松手就停，那是**点动**。

它作为「块级导入 XML 骨架」的样板是合格的（`AttributeList` 空 `<Namespace/>`、`FlgNet` 命名空间处理等都对）；作为「起保停逻辑」的样板是错的。**引用它时必须说清引的是哪一半。**

### 变量表

| 名称建议 | 数据类型 | 方向/存储区 | 说明 |
|---|---|---|---|
| `启动按钮` / `PB_Start` | Bool | **I** | 现场常开（NO）按钮 |
| `停止按钮` / `PB_Stop` | Bool | **I** | **现场按常闭（NC）接线** —— 见下文 |
| `电机运行` / `Motor_Run` | Bool | **Q**（或 M 后再驱动 Q） | 输出到接触器线圈 |
| `热保护正常` / `OL_OK` | Bool | **I** | 热继电器/变频器故障，NC 接线 |
| `允许运行` / `Enable` | Bool | M / DB | 汇总允许条件（方式、安全、无报警） |

**接线与程序侧的对应关系（这里最容易绕晕，写清楚）**

| 现场接线 | 未按下时 PLC 输入 | 程序里该用 | 断线时表现 |
|---|---|---|---|
| 停止按钮 **NC**（推荐） | **1** | **常开触点**（`Contact`，不带 `Negated`） | 输入变 0 → 停机 ✅ **失效安全** |
| 停止按钮 **NO**（不推荐） | 0 | 常闭触点（`Contact` + `<Negated>`） | 输入恒 0 → **停不下来** ❌ 潜伏失效 |

> **总表的 ASCII 图（`---| |---------|/|---`，停止画成常闭触点）对应的是「现场 NO 接线」，与总表正文「按 NC 接线、程序用常开触点」的要求**不一致**。本文按正文口径（NC 接线 + 程序常开触点）书写，差异已列入文末《与总表的差异》。**

### 参数与整定

| 参数 | 值 | 依据 |
|---|---|---|
| 按钮去抖 | **10–30 ms** | 机械触点弹跳典型 5–20 ms（《整定值》2.1） |
| 去抖实现位置 | **优先 CPU 硬件输入滤波**（CPU 属性 → 数字量输入 → 输入滤波时间），而非程序里加 TON | 不占扫描周期；对高速计数输入是唯一正确做法 |
| 接触器互检延时（如做回读） | 100–200 ms | 吸合典型 10–30 ms、释放 5–20 ms，取余量（《整定值》2.2） |

⚠️ **不要给安全相关输入加长滤波** —— 滤波时间直接加进 ISO 13855 `S = K×T + C` 的 T，滤波多 50 ms，安全距离要多 100 mm（手速 K=2000 mm/s）。

### 常见坑　⚠️【待老殷审】

- **停止按钮按 NO 接线是潜伏失效。** 断线、端子松、触点烧毁、失电，NO 接线下全部表现为「停不下来」，而且**平时完全看不出来**。NC 接线下这些故障全部导向停机侧。
  → 纯操作用的普通停止按钮用 NC 属 **【惯例，非标准强制】**（《整定值》第三节③明确：没找到标准原文字面这么写）。
  → **安全相关**的位置检测/停止属 **【标准强制】**：IEC 60204-1:2016 **10.1.4** —— "Position sensors in circuits with safety-related control functions… shall have direct opening action (see IEC 60947-5-1) or shall provide similar reliability"。
- **自锁引中间位而非输出本身** → 多一个扫描周期延迟；在跨 OB / 跨块场景下会出现"按了没反应，再按一下才行"。
- **同一个 Q 在多处被写（双线圈）** —— 🔴 **TIA 完全不警告**。CPU 每周期从过程映像写物理点，程序内对同一 Q 的多次写**后写覆盖先写**，前面那段逻辑**完全失效但看起来在工作**（在线监视还能看到能流）。
  《LAD陷阱》3.2 双向证实：官方文档无相关警告文本，整个 `BlockLogic` 消息目录（3256 条）搜 `coil|multiple assign|written more|assigned more` **零命中**。
  → 只能靠工具查：交叉引用 **F11**、**Show overlapping access**（V14 起）、`程序信息 > 分配列表`。
- **一个 network 的线圈有上限**。【本机，`BL_TOO_MANY_COILS`】
  EN: `Too many coils in one network. A maximum of 16 parallel coils is allowed.`
  ZH: `一个程序段中的线圈太多。最多允许有 16 个并联线圈。`
- **线圈前必须有逻辑运算**。【本机】
  EN: `The coil/assignment requires a preceding logic operation.` / ZH: `线圈/分配需要一个前导逻辑运算。`
  另有 EN: `A coil/assignment is required.` / ZH: `需要线圈/分配。`（网络必须以线圈或盒子指令结束）
- **急停不要串在这个回路里当唯一保护。** 见 4.2 `safety-interlock`。标准 PLC 的梯形图**不能**是"移除危险能量"链上的必要环节。
- **热保护/变频器故障必须进停止条件**，且按 NC 接线。

### 上机前必须确认　⚠️【待老殷审】

- [ ] 停止按钮**实际接线是常闭（NC）** —— 用万用表量，不要听人说
- [ ] 程序里停止用的是**常开触点**（与 NC 接线配对），不是常闭触点
- [ ] 急停回路已**独立硬线**设计，经安全继电器直接切断动力，**不经过 PLC 程序**　【惯例，本项目强制】
- [ ] 电机热保护 / 变频器故障已接入停止条件，且为 NC 接线
- [ ] 交叉引用（F11）查过：该输出**没有在别处被第二次写入**
- [ ] 输入滤波时间已设，且**安全相关输入没有被加长滤波**
- [ ] 上电首次扫描时输出确实为 0（不会自启）
