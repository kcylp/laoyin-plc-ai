# 从零新建工程作战手册（工作流 A）

**适用** 用户要做一个**全新**博途工程（不涉及已有工程改造）
**对标** 竞品《从零新建工程的作战手册》
**执行者** AI（老殷工控PLC助手）
**版本** v1 · 2026-08-23

---

## 这份手册解决什么问题

没有它，AI 每次接到需求都是自由发挥：这次先建 CPU 再写块，下次先写块发现 CPU 没建；这次块叫 `FB_Motor`，下次叫 `MotorControl`；这次写了急停，下次忘了。**输出不可复现，就不是产品。**

有了它，同一个需求问十次，出来的工程结构、命名、注释、验证步骤**一致**。这是竞品做对的第一件事。

---

## 阶段 0 · 接活前的自检（不做这一步后面全白干）

**必须按顺序确认，任一项不过就停下来告诉用户，不要硬着头皮往下做。**

| # | 检查 | 不过怎么办 |
|---|---|---|
| 0.1 | 博途连接是否可用（`/api/tia/mcp/status`） | 引导用户「连接博途」；若连不上，导流到一键环境诊断（TASK-004） |
| 0.2 | 博途版本是否被本版本支持 | 明确告知版本不匹配，不要尝试（TASK-005） |
| 0.3 | 需求里 **CPU 型号 + 订货号 + 固件版本** 是否明确 | **必须问用户**。这三样决定了可用指令集、I/O 地址范围、PTO 通道数。猜错等于白做 |
| 0.4 | 需求里 **编程语言**（LAD/SCL/混合）是否明确 | 默认 LAD（工控现场主流），但要说明「已按梯形图处理，需要 SCL 请告诉我」 |
| 0.5 | 是否涉及**运动控制 / 块调用** | ⚠️ 见《技术底座_FlgNet指令实证表》第三节 —— 当前**无已验证写法**。必须诚实告知用户这部分需手工在博途添加，不要生成猜测的 XML |
| 0.6 | 是否涉及**安全功能**（急停、光栅、安全门） | 必须告知：安全功能不能靠标准 PLC 程序实现，需硬线 + 安全继电器/F-CPU。见《安全设计要求》 |

**0.3 和 0.5 是最容易被跳过、代价最大的两条。**

## 阶段 1 · 需求结构化（把大白话变成工程语言）

用户说的是「6 工位转盘」，你要产出的是一张表。**这一步的产物要给用户确认，不要直接开干。**

### 1.1 设备方案（先讲清机械怎么动）
- 执行机构类型：伺服 / 步进 / 变频 / 气缸 / 电磁阀
- 驱动方式：PTO 脉冲 / PROFINET 通信 / 模拟量 / 纯开关量
- 动作节拍：一个循环里依次发生什么，每步的触发与结束条件
- 参数化的量：哪些数（速度、距离、延时、数量）应该做成可改的 DB 参数，而不是写死在程序里

**判断标准**：现场调试时会反复改的数，一律进 DB；不会改的才写死。

### 1.2 I/O 分配表

| 列 | 要求 |
|---|---|
| 地址 | 按 CPU 实际 I/O 范围分配。1214C DC/DC/DC 板载 DI 14 点（I0.0-I1.5）、DQ 10 点（Q0.0-Q1.1） |
| 名称 | 中文符号名，见《命名规范》 |
| 类型 | **常开 / 常闭**必须标明 |
| 说明 | 一句话讲清物理含义 |

**三条硬约束**（详见《安全设计要求》）：
1. **停止按钮、急停、限位开关、热保护一律按常闭（NC）接线处理** —— 断线即停，这是失效安全原则
2. **急停不占用普通输入做安全功能** —— 程序里读急停的辅助触点只做状态联锁与显示，真正的切断必须硬线
3. **PTO 占用的输出（如 Q0.0/Q0.1）不能再作普通输出使用**

### 1.3 程序结构表

| 块 | 类型 | 职责 |
|---|---|---|
| Main | OB1 | 只做「依次调用」，不写业务逻辑 |
| Fb安全 | FC 或 FB | 急停联锁、方式切换、起保停、报警锁存与汇总、指示灯 |
| Fb动作 | FB | 具体执行机构控制 |
| Fb流程 | FB | 步序状态机 |
| Db参数 | 全局 DB | 现场可调参数 + 中间量 |

**结构原则**：
- **OB1 不写逻辑**，只调用。这样看 OB1 就能看懂整个工程的骨架
- **安全相关逻辑集中在一个块**，不要散落各处 —— 审查时能一眼看完
- **状态机独立成块**，不要和执行逻辑混在一起
- **参数集中在 DB**，改参数不动程序

### 1.4 操作逻辑说明
按「手动方式 / 自动方式 / 急停与报警」三段写清楚。每段回答：怎么进入、怎么操作、怎么退出、异常怎么办。

**必须明确写出**：急停恢复后是否自动重启。**标准做法是不自动重启，必须人工复位**。

### 1.5 把 1.1-1.4 给用户确认

> 以上是我理解的方案。**请确认 I/O 分配和操作逻辑**，尤其是标注了「常闭」的那几个输入是否与现场接线一致。确认后我开始生成程序。

**这一步不能省。** I/O 分配错了，后面全部返工；常开常闭搞反了，可能出安全事故。

## 阶段 2 · 建工程骨架

### 2.1 创建项目 + 添加 CPU
用 `ScaffoldProject` / `CreateProject`，参数带上阶段 0.3 确认的型号、订货号、固件版本。

### 2.2 建变量表
按 1.2 的 I/O 分配表建 PLC 变量表。**先建变量表，再写程序** —— 顺序反了会生成一堆引用不存在符号的代码。

### 2.3 建 DB
按 1.1 识别出的可调参数建全局 DB，**每个成员给出合理的初值和注释**。占位值必须在交付文档里标注「需现场实测后修改」。

### 2.4 建工艺对象（如涉及运动控制）
⚠️ 当前 XML 侧无已验证写法。**如实告知用户此步需在博途中手工完成**，并给出具体指引（要建什么类型的工艺对象、关键组态项是哪些）。

## 阶段 3 · 逐块生成 → 即时编译（竞品做对的第二件事）

**核心纪律：一块一编译，0 错才继续。不要一口气生成完再统一编译。**

生成顺序（按依赖倒序，被依赖的先做）：
```
1. Db参数        （其他块都要引用它）
2. Fb安全        （最独立，且是安全相关，先做先审）
3. Fb动作        （可能引用 Db参数）
4. Fb流程        （引用 Db参数，被 Main 调用）
5. Main          （调用上面全部）
6. 全工程编译
```

每一块的流程：
```
生成 XML
  → XSD 校验（Test-YinFlgNet）
  → 预检（/api/tia/preflight）
  → 用户确认
  → 写入
  → 编译该块
  → 0 错？是 → 报「已完成，接进主程序: <调用方式>」，进入下一块
             否 → 走《编译错误诊断》，修复后重来（最多 3 轮）
```

**报「接进主程序」这件事要明确说出来**（竞品每块编译完都提示了 `lad Main call:FbSafety@InstFbSafety`）—— 否则用户不知道这个块还没被调用，会以为已经能跑了。

### 阶段 3 的两个禁止
- ❌ **禁止跳过 XSD 校验直接导入** —— 校验几百毫秒，导入失败排查半小时
- ❌ **禁止某块编译不过就继续做下一块** —— 错误会累积，最后分不清是谁的问题

---

## 阶段 4 · 全工程编译 + 保存

全工程编译（`CompileSoftware` / `CompileAndDiagnosePlc`），确认 0 错误。

**警告要逐条看，不要因为「只是警告」就放过。** 常见的有意义警告：变量未使用（可能是漏写逻辑）、隐式类型转换（可能精度丢失）、块接口变更（调用方可能没同步）。

保存工程（`SaveProject`）。⚠️ **保存会把所有修改固化**，这是 TASK-006 认定的危险操作，必须过用户确认。

---

## 阶段 5 · 生成交付文档

见《交付文档模板》。至少包含：设备方案、程序结构表、I/O 分配表、变量表、操作逻辑、**上机前必须现场确认清单**、修改履历。

**「上机前必须现场确认」这一节永远不能省。** 编译 0 错误只证明语法和引用对，不证明逻辑对、不证明接线对、不证明整定值对、更不证明安全。

---

## 阶段 6 · 收尾话术

不要说「程序写好了，可以用了」。要说：

> 工程已完成，全工程编译 0 错误 0 警告，文件在 `<路径>`。
>
> **接下来必须做的三件事**（编译通过 ≠ 可以上机）：
> 1. 在博途里**逐网络人工审查**一遍 —— 我生成的是草稿
> 2. 用 **PLCSIM 仿真**跑一遍完整流程，尤其是急停和异常分支
> 3. 核对交付文档里的《上机前必须现场确认》清单，逐项打勾
>
> 其中标注了「占位值」的参数（<列出具体是哪几个>）必须现场实测后修改。

## 附：工作流选择规则

| 情况 | 走哪个 |
|---|---|
| 未连接博途，或连上了但工程为空 | **工作流 A**（本手册） |
| 已连接，工程里已有程序块 | **工作流 B**（存量工程改造）—— 重点是不破坏现有逻辑，写入前必须 diff、必须查调用方 |
| 用户只想看懂现有程序 | **工作流 C**（读懂现有程序）—— 只读，不写 |
| 用户拿着编译错误来问 | **工作流 D**（排查编译错误） |

判定依据：`/api/tia/mcp/status` 的连接状态 + 软件树的程序块数量。**判定结果要告诉用户**（「这是全新工程，走工作流 A」），让他知道你在按什么套路做事 —— 这也是竞品给人信任感的地方。
